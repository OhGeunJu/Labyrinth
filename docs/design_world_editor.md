# 월드 에디터 설계 — 2026-08-27, **1—4단계 구현됨**

**한 줄**: **저작 씬에 세계 전체가 서 있고, 게임을 켜면 그것이 청크로 스트리밍된다.**

```
World.unity (저작 씬)                     Resources/WorldContent/{x}_{y}.asset
  세계 전체가 진짜 오브젝트로 서 있다   ──굽기──▶   청크별 목록
  유니티에서 그냥 편집한다                         런타임이 이것만 읽는다
```

저작 씬은 **빌드에 안 들어간다.** 게임은 구운 청크 에셋만 읽는다.

---

## 왜 이 모양인가 — 앞선 안을 접는다

처음 적었던 안은 **`Open Area` → 편집 → `Save Area`** 왕복이었다. 3×3 청크만 펼쳐 고치고
다시 접는 방식이다. 접는 이유:

| | 왕복(구안) | 저작 씬(이 안) |
|---|---|---|
| 여는 일 | 매번 자리를 찾아 연다 | **늘 열려 있다** |
| 경계를 넘는 편집 | 연 영역 밖으로 나간 것을 특별 취급해야 한다 | **없는 문제다** — 굽는 순간에만 좌표로 나눈다 |
| 유니티 기능 | 펼친 영역 안에서만 | **전부 그대로** — 다중 선택 · 복제 · 실행 취소 · 검색 · 프리팹 오버라이드 |
| 멀리 있는 둘을 같이 보기 | 못 한다 | 된다 |
| 도구 코드 | 열기·저장·경계 규칙 셋 | **굽기 하나** |

**왕복은 "세계가 씬에 못 들어간다"는 전제 위에 세운 우회로였다.** 그 전제가 지형에만 참이고
저작한 물건에는 거짓이라, 우회로가 통째로 필요 없어진다.

---

## 무엇이 씬에 들어가고 무엇이 안 들어가나

**이 구분이 이 설계의 전부다.**

| | 씬에 | 왜 |
|---|---|---|
| 저작한 물건 — 마을·건물·NPC·소품 | **들어간다** | 수천 개다. 유니티 씬이 감당하는 규모다 |
| 조각한 지형 청크 | **들어간다** | 손댄 것만이다. 수십 개 |
| 안 조각한 지형 | **안 들어간다** — 다만 **보이기는 한다** | 저장은 전부면 정점 6,712만 · **550MB**. 원본이 **함수**라 넣을 것이 없다. 대신 씬 뷰 둘레만 에디터에서 세운다(아래) |
| 뿌리는 것 — 나무·바위 | **안 들어간다** | 수십만 개다. 좌표 해시라 **저장할 것이 없다** |

**"씬에 있는 것이 진짜다"** — 연구 그래프가 이미 쓰는 규칙 그대로다(`ResearchGraphBaker`).
씬에 없는 것은 함수이거나 해시다.

### 안 들어간다 ≠ 안 보인다 (2026-08-27 보강)

**"씬에 진짜 월드가 있으면 좋겠다"**는 물음에 처음 답할 때 *물건*만 넣고 **땅을 빼먹었다.**
데이터로는 맞았지만(아래), 저작 씬을 열면 **마을이 허공에 떠 있었다** — 땅이 안 보이면
*"저 산 너머에 마을을 놓자"*가 성립하지 않는다.

**땅을 저장하지 않는 것과 안 보이는 것은 다른 문제다.** 그래서 **에디터에서도 스트리밍을
돌린다**(`WorldSceneTerrain`) — 런타임이 뷰어 둘레만 세우듯, 여기서는 **씬 뷰 카메라 둘레**
5×5 청크(1,280m)를 진짜 해상도로 세운다. 저작 루트가 있는 씬에서만 돌고, 플레이 중에는
멈춘다(그때는 진짜 스트리머가 세운다).

- **씬에 저장되지 않는다**(`HideFlags.DontSave`) — 안 걸면 25청크가 `World.unity`에 박힌다.
- **떠나면 `TerrainData`까지 버린다** — 오브젝트만 지우면 돌아다닐수록 샌다.
- **콜라이더를 단다.** 프리팹을 씬 뷰로 끌어다 놓을 때 유니티가 콜라이더에 스냅하므로, 없으면
  물건이 원점 근처에 떨어진다. **`E. World Preview`에 콜라이더를 안 달았던 것과 정반대 이유다**(그 도구는 2026-09-12에 지웠다) —
  저쪽은 부정확한 저해상도라 짚으면 안 되고, 이쪽은 진짜 높이다.
- **조각 중인 청크(`__TerrainEdit`)는 건너뛴다** — 같은 자리에 둘이 서면 z-파이팅이 난다.
- **도메인 리로드를 건너 살아남은 것을 도로 잡는다** — `DontSave`는 리로드로 안 죽어서, 안
  잡으면 화면에는 있는데 사전은 비어 **영영 안 치워지는 청크**가 남는다.

### 지형이 안 들어가도 되는 진짜 이유

**물건이 높이를 저장하지 않기 때문이다.** `Position`은 XZ뿐이고 Y는 런타임에
`TerrainHeight.At()`로 지면에 붙인다. 그래서 **저작할 때 정확한 지형이 없어도 데이터가 맞다** —
XZ와 방향만 정하면 된다.

지형은 *보기 위해* 필요하지 *데이터를 위해* 필요한 것이 아니다. 그래서 **보여 주는 길이
셋이고 저장은 하나도 안 늘어난다**:

- **발밑** — `WorldSceneTerrain`이 씬 뷰 둘레 1,280m를 진짜 해상도로 세운다(콜라이더 있음)
- **멀리 볼 때** — ~~`E. World Preview`(저해상도 한 장)~~ **2026-09-12에 지웠다**: 높이를 `MapHeight`(잔기복·델타를 뺀 값)에서 뽑아 기본 6배로 부풀려 그렸으니 **실제 지형과 다른 판**이었고, 지하에서는 굴이 애초에 안 보인다(바위는 런타임 물건이다). 굴의 모양은 `World → 2. Preview Cave Map`이 **판정과 같은 함수로** 답한다
- **조각할 때** — `1. Open Chunk`로 그 청크를 붓으로 만질 수 있게 연다

## 결정 사항

| # | 항목 | 결정 | 근거 |
|---|---|---|---|
| 1 | 저작 표면 | **씬 하나(`World.unity`)에 세계 전체** | 유니티를 그대로 쓴다. 도구가 흉내 낼 수 없는 것들이 공짜로 딸려 온다 |
| 2 | 빌드 포함 | **안 넣는다** (Build Settings에서 뺀다) | 넣으면 런타임에 세계 전체가 메모리에 올라온다. 스트리밍이 있는 이유가 사라진다 |
| 3 | 굽는 단위 | **청크별 SO** `Resources/WorldContent/{x}_{y}.asset` | `TerrainDelta`와 같은 패턴. 조회가 O(1)이고 git diff가 국소적이다 |
| 4 | SO냐 JSON이냐 | **SO** | 기준은 이미 있다(`docs/data.md`): *"다른 에셋이 GUID로 가리켜야 하는가"*. 프리팹 참조가 **필수**라 JSON으로는 못 가리킨다 |
| 5 | 높이 | **`Position`은 XZ + `YOffset`**, 절대 Y 아님 | 절대 Y로 구우면 **지형을 다시 조각한 순간 마을이 공중에 뜨거나 파묻힌다** |
| 6 | 어느 청크의 것인가 | **좌표가 정한다.** 하이어라키 부모는 **눈을 위한 폴더일 뿐** | 답이 둘이면 어긋난다 — 물건을 끌어 옮겼는데 부모가 그대로면 어느 쪽이 맞나. `TerrainDelta`의 정점 소유권과 같은 규칙 |
| 7 | 펼치는 방식 | **프리팹 인스턴스, 언팩 금지** | 굽기가 `PrefabUtility.GetCorrespondingObjectFromSource`로 되짚는다. 언팩하면 어느 프리팹이었는지 알 길이 없다 |
| 8 | 신원 | **안정 `Id`(GUID 문자열)**, 인덱스 아님 | 지금 `_sitesUp.Contains(i)`가 **배열 인덱스**를 신원으로 쓴다. 저작이 바뀌면 가리키는 것이 달라진다 |
| 9 | 굽는 결과물 | **데이터 목록**(프리팹 참조 + 좌표), 청크 프리팹 아님 | 청크를 통째로 프리팹으로 구우면 한 번에 세울 수 있어 빠르지만, **`Persistent`가 물건마다 갈린다**(마을은 안 내리고 장식은 내린다). 섞인 프리팹은 그걸 못 가른다 |
| 10 | NPC | `WorldObject`에 **선택적 `PawnSpecData`** | 폰 명세는 이미 다 있다(`PawnSpec`·`LoadoutData`·`NpcData`). *"저작 < 주입"* 우선순위에 그대로 얹힌다 |
| 11 | 퀘스트 | **범위 밖.** 훅 한 칸(`QuestId`)만 열어 두고 비운다 | 지금 코드에 `Quest`가 하나도 없다. 저장·플래그·저널·조건·보상이 통째로 없다 |
| 12 | 런타임 세이브 | **범위 밖** | 이건 **저작 데이터**다. *"플레이 중 바뀌는 것은 런타임이 들고 원본은 손대지 않는다"*(`WorldMapData` 주석) |

## 데이터

```csharp
// Resources/WorldContent/{x}_{y}.asset — 그 청크에 놓인 것 전부
public class WorldChunkContent : ScriptableObject
{
    public Vector2Int    Chunk;
    public WorldObject[] Objects;
}

[Serializable]
public class WorldObject
{
    public string     Id;          // 안정 신원 — 순번이 아니다
    public string     Name;
    public GameObject Prefab;      // GUID 참조 → 그래서 SO다
    public Vector2    Position;    // 월드 XZ (절대)
    public float      YOffset;     // 지면에서 띄울 높이
    public float      Yaw;
    public bool       Persistent;  // 한 번 서면 안 내린다 (상태를 든 곳)
    public bool       FromMap;     // 도구가 지도에서 뽑은 것 — 손으로 놓은 것은 안 건드린다

    public PawnSpecData Spec;      // 폰이면 — 비우면 굴린다
    public string       QuestId;   // 훅. 지금은 아무도 안 읽는다
}
```

**지금 `WorldSite`가 이걸로 승격되는 것이다** — 필드가 셋 늘고(`Id`·`Spec`·`QuestId`) 사는
곳이 씬 배열에서 청크 에셋으로 옮겨진다.

### 씬 쪽 — `WorldObjectTag`

저작 씬의 인스턴스에 붙는 작은 컴포넌트. **트랜스폼이 답할 수 없는 것만** 든다.

```csharp
public class WorldObjectTag : MonoBehaviour
{
    public string       Id;          // 굽기가 발급하고 유지한다
    public bool         Persistent = true;
    public bool         FromMap;
    public PawnSpecData Spec;
    public string       QuestId;
}
```

**자리·방향은 트랜스폼이 답한다** — 여기 또 적으면 씬에서 끌어 옮겼을 때 둘이 갈린다.
`YOffset`은 `transform.position.y`에서 그 자리 지면 높이를 뺀 값으로 굽는다.

## 굽기

```
DungeonColony → World → Bake World
```

1. 저작 씬의 콘텐츠 루트를 훑는다
2. 각 인스턴스를 **좌표로** 청크에 나눈다 (결정 6 — 부모는 안 본다)
3. 프리팹 원본을 되짚는다 (`GetCorrespondingObjectFromSource`)
4. `Id`가 없으면 발급해 씬에 되써 둔다 — **다음 굽기에도 같은 신원이어야 한다**
5. 청크별로 에셋을 쓴다. **내용이 없어진 청크의 에셋은 지운다**
6. 조각한 `Terrain`이 씬에 있으면 델타도 같이 굽는다 (지금 `2.`가 하는 그것)

### 함정 — 미리 적어 둔다

- **되짚지 못한 것은 굽지 말고 경고할 것.** 프리팹 인스턴스가 아닌 것(씬에서 만든 빈
  오브젝트 등)은 굽을 방법이 없다 — **조용히 버리면 편집한 것이 사라진 것으로 보인다.**
- **빈 청크의 에셋을 지울 것.** 안 지우면 씬에서 지운 마을이 게임에는 그대로 선다.
- **`Id`를 씬에 되쓸 것.** 굽을 때마다 새로 발급하면 신원이 매번 바뀌어, 세이브가 *"이
  마을은 털렸다"*를 기억할 수 없게 된다.
- **`Resources.Load`는 "없다"는 사실도 기억할 것.** 대부분의 청크에는 에셋이 없다 —
  `TerrainHeight.DeltaOf`가 이미 그렇게 한다.
- **`Persistent` 추적 키를 인덱스에서 `Id`로 바꿀 것**(`_sitesUp`).
- **저작 씬을 Build Settings에 넣지 말 것**(결정 2). 다만 **그것만으로는 안 막힌다** —
  에디터의 Play는 **열려 있는 씬을 그대로 들고 들어간다.** 그러면 마을·소굴 수백 곳이
  한꺼번에 살아나서 **그 안의 NPC가 지형 없는 허공에서 떨어지고**(`PawnMover`의 낙하 복구가
  수백 줄씩 경고를 뱉는다), 스트리밍이 세운 것과 **두 벌**이 되어 같은 마을이 두 번 선다.
  그래서 **`WorldAuthoringRoot`가 `Awake`에서 스스로 꺼진다**(2026-08-27, 실제로 겪었다).
  `[DefaultExecutionOrder(-30000)]` — 자식들이 깨어나기 전에 꺼야 한 프레임도 안 돈다.
- **에디터에서 펼친 폰은 `Awake`가 안 돈다**(에디트 모드에서는 `MonoBehaviour`가 안 깨어난다).
  스탯도 세력도 안 잡는다 — **그래서 수천 개를 펼쳐 놓아도 안전하다.** 다만 그 말은
  **씬에서 보이는 폰은 명세가 안 얹힌 껍데기**라는 뜻이라, 자리와 방향만 보고 잡아야 한다.

### 되돌리는 길 — `Load World Into Scene`

청크 에셋 전부를 읽어 저작 씬에 펼친다. **이행할 때 한 번** 쓰고, 그 뒤로는 **저작 씬이
원본**이다. 두 방향을 다 상시로 쓰면 어느 쪽이 최신인지가 또 규칙이 된다.

## 규모 — 실제로 감당되나

| | 개수 | 비고 |
|---|---|---|
| 마을 100곳 × 오브젝트 30개 | 3,000 | |
| 손으로 놓은 소품·NPC | 2,000 | |
| **합** | **~5,000** | 유니티 씬이 무리 없이 감당한다 |

- **씬 파일**: 프리팹 인스턴스는 오버라이드만 직렬화하므로 하나에 수백 바이트다.
  5,000개면 **수 MB**. git이 감당한다(다만 **merge는 아프다** — 혼자 작업하는 전제).
- **하이어라키**: 5,000개는 괜찮고 **5만을 넘으면 느려진다.** 그때가 오면 지역별 부모를
  꺼 가며 작업한다(부모는 어차피 눈을 위한 폴더다 — 결정 6).
- **씬 뷰**: 16km 상공에서 보면 전부 절두체 안이라 다 그려진다. 멀리 볼 때는 지역 부모를
  끄면 된다(`E. World Preview`는 2026-09-12에 지웠다).

## 바이옴은 남는다 — 죽는 것은 격자의 다른 절반이다

*"이제 월드맵 기반이 아닌데 바이옴을 따로 나눌 필요가 있나"*(2026-08-27 물음). **격자가 두
가지 일을 겸하고 있어서 답이 갈린다.**

```csharp
// WorldMapData.Node
public Biome            Biome;    // ← 남는다. 오히려 더 중요해졌다
public WorldNodeContent Content;  // ← 저작 표면으로서는 죽는다
```

### 바이옴은 이어진 세계라서 더 중요해졌다

여섯 곳이 읽는다 — `BiomeTerrain.Of`(지형 성격, **정점마다**) · `BiomeTier.Of`(난도 1~5,
티어마다 전력 +35%) · `BiomeContent`(나오는 자원·무리) · `WorldDeposits`(매장) ·
`TownMarket`/`TownRecruits`(마을 물건과 사람) · `TerrainHeight.MapColor`(지도 색).

**이것이 `design_progression.md`의 루프 그 자체다** — 탐험 → 더 험한 지역 → 더 좋은 자원.
빼면 지형이 노이즈 한 벌이 되고 세계가 **어디를 가도 같은 곳**이 된다. 노드로 이동하던
시절에는 *"칸마다 다른 성격"*이 UI였지만, 이어진 세계에서는 **그것이 세계가 넓은 유일한
이유**다.

### `Content` 축은 저작 씬이 대신한다 — 다만 지금은 못 지운다

이유가 저작이 아니라 **런타임**이다. 무리·소굴·마을·전초기지·정착지가 아직 **노드 좌표로
돈다**(`WorldBandManager` · `WorldLairs` · `TownMarket` · `TownRecruits` · `OutpostManager` ·
`SettlementManager`가 전부 `WorldMap.Instance`를 쓴다). 저작 씬으로 마을을 옮겨도 **무리가
어느 소굴에서 나오는지는 여전히 노드가 답한다.**

그래서 순서는 이렇다: **저작 표면부터 옮기고**(`5. Place Sites`가 씬에 놓게 — 3단계),
런타임의 노드 의존은 **그다음 별건**이다. 한꺼번에 하면 무엇이 깨졌는지 못 가른다.

### 바이옴 저작 표면 — 격자에서 볼륨으로 (나중)

지금은 2D 창에서 64×64 격자를 칠한다(한 칸 = 256m = 청크 하나). 씬 저작과 따로 놀고,
격자에 갇혀 *"강 따라 늪"* 같은 모양이 안 나온다.

**볼륨이 자연스러운 방향이다** — `TerrainFeature`(산·분지)와 똑같이 좌표 + 반경으로 *"여기는
사막"*을 씬에 놓는다. 손잡이는 이미 있다(`TerrainStreamerEditor`).

**다만 그대로 런타임에 쓰면 안 된다.** `BlendedBiome`은 **정점마다** 불리는데(청크 하나가
16,641번) 볼륨 N개를 매번 훑으면 격자 배열 조회보다 훨씬 비싸다. 그래서:

```
저작 = 씬의 볼륨  ──굽기──▶  바이옴 격자  ──▶  런타임(지금과 동일)
```

지형 델타·연구 그래프와 **같은 패턴**이다 — 저작은 편한 도구로, 런타임은 내 데이터로.
**런타임은 한 줄도 안 바뀐다.** 급하지 않다 — 격자 칠하기는 작동하고 `8. Generate Biome Map`이
온도×습도로 씨도 뿌린다. 막힌 것은 저작 왕복이지 바이옴이 아니다.

# 노드 걷어내기 — 별건 (2026-08-27, **완료**)

무리·소굴·마을·전초기지·정착지가 아직 **`Vector2Int` 노드**로 돈다. 이어진 세계에는 이동하는
칸이 없는데도 그렇다.

## 노드가 답하던 물음은 셋이다

| 물음 | 지금 | 바뀌면 |
|---|---|---|
| **주소** — 이 소굴은 어느 것인가 | `Vector2Int Node` | **`WorldObject.Id`** (월드 에디터 1단계에서 생겼다) |
| **자리** — 어디에 있나 | `SurfacePoint(node)` | **`WorldObject.Position`** (이미 있다) |
| **이웃·거리** — 다음에 어디로 | `WorldMap.Distance` / `Neighbors` | 월드 좌표 직선거리 + 반경 검색 |

**무리는 이미 반쯤 넘어와 있었다** — `WorldBand.Position`이 `Vector3`이고 주석에 *"격자에
매이지 않는다"*고 적혀 있다. 남은 것은 `Home`·`Goal`·`Node` 셋이다.

## 새로 필요한 것은 하나 — 좌표 색인

**`WorldSites`**(2026-08-27 완료) — 구운 청크 에셋 **전부**를 훑어 만든 장소 색인.
`Of(kind)` / `Nearest(kind, from)` / `Within(kind, from, r)` / `ById(id)`.

- **`Resources.LoadAll`을 쓴다** — `TerrainHeight.DeltaOf`가 일부러 한 청크씩 읽는 것과 **반대
  방향**이다. 저쪽은 손댄 청크만 에셋이 있어 통째로 읽으면 없는 것까지 훑지만, 여기는 **지도가
  세계 전체를 한 번에 그리고** 무리는 가 보지 않은 곳의 마을도 알아야 한다
  (`WorldLairs.BuildAll`이 미리 다 깨우는 그 이유). **전부 필요하면 전부 읽는 것이 맞다.**
- **`Kind == Empty`는 장소가 아니다** — 장식·소품·폰이다. 넣으면 지도가 물건으로 뒤덮이고
  *"가장 가까운 마을"*이 바위를 짚는다.
- **못 찾으면 `IsValid`가 거짓인 것을 준다** — `null`을 돌려주면 부르는 쪽마다 검사를 빠뜨린다.

### 딸려 온 것 — `WorldObject.Kind`

전에는 **저작한 격자가 종류를 들고 있었다**(`WorldMapData.Node.Content`). 그래서 손으로 놓은
마을은 **게임 지도에 안 떴다** — 격자에 안 찍혔으니까. 물건이 제 종류를 들면 **세계에 실제로
있는 것**이 그대로 화면에 뜨고, 한 지역에 소굴 하나라는 격자의 제한도 없어진다.

**`Kind` 칸이 생기기 전에 놓인 것(1단계 이행분 128개)은 전부 `Empty`다** — `5. Place Sites`가
이미 있는 것도 지도대로 고쳐 준다. 안 고치면 지도에서 통째로 사라진다.

   - **친 소굴은 런타임 상태다**(`WorldLairs._gone`). 전에는 `SetContent(Empty)`로 **저작 격자를
     고쳐서** 지웠는데, 자리가 굽힌 에셋으로 오면서 그럴 수가 없다 — **저작물에 플레이 중의
     일을 쓰면 안 된다.** 지도도 `IsGone`을 보고 안 그린다(표식만 남으면 친 소굴과 안 친
     소굴이 지도에서 같아 보인다).
3. ~~**`WorldBandManager`·`WorldBand`의 이동을 좌표로.**~~ — **2026-08-27 완료.**

   **여기서 드러난 것이 하나 있다: 무리 체계가 통째로 죽어 있었다.** `Start()`가
   `WorldMapView`(옛 3D 월드맵)를 못 찾으면 **스스로 `enabled = false`** 했는데, 그 화면의
   진입로를 끊은 뒤로 그 조건에 걸려 있었다. 게다가 `BandMaterializer`는 **씬에 아예 없다** —
   토큰이 실제 폰이 되는 길이 안 물려 있다.

   - **옛 화면을 안 찾는다.** 지도 격자가 아니라 세계 좌표 위에서 돈다.
   - **지면은 함수가 답한다**(`TerrainHeight.At`). 격자 메시를 짚으면 그 화면이 없을 때
     `NullReference`로 이동이 통째로 멎고, 지도 반대편의 무리는 제 높이를 모른다.
   - `Home` → **`Vector2` + `HomeId`**, `Goal` → **`Vector3`**, `Node`는 자리에서 파생.
     상단 시계(`_nextCaravanAt`)도 신원이 키다 — 마을을 옮겨도 시계가 안 흔들린다.
   - **저작한 반지름은 지역 수라 미터로 바꿔 쓴다**(`RoamMeters`/`PatrolMeters`). 눈금을
     상수로 안 박는 이유: 지역 크기를 바꾸면 거리감도 같이 따라와야 한다.
   - 마을이 하나뿐이면 상단은 **내 거점**으로 간다(교역로가 저절로 생긴다). 옛 코드가
     `WorldMap.Settlements`를 봤는데, 그건 4단계에서 걷어낼 격자라 `DungeonCore.All`로 옮겼다.

   **`BandMaterializer` 배선도 끝났다**(2026-08-27) — `Terrain → 0. Setup World Streaming`이
   같이 붙인다. 없으면 `WorldBandManager`가 토큰만 굴리고 **무리가 영영 실제 폰이 되지
   않는다**(습격이 예고돼도 아무도 안 온다).

   그러면서 **루트 이름이 겹쳐 있던 것**이 드러났다 — 저작 씬의 루트도, 스트리밍 루트도
   `"World"`였다. 저작 씬을 같이 열어 두면 `GameObject.Find("World")`가 어느 쪽을 집을지
   알 수 없고, **저작 루트에 스트리머가 붙으면 판이 열릴 때 그것이 통째로 꺼져 세계가 안
   선다**(저작 루트는 `Awake`에서 스스로 끈다). 저작 쪽을 `WorldAuthoring`으로 갈랐고,
   배선 도구는 **이름보다 컴포넌트를 먼저 찾고** 저작 루트면 거절한다.
4. ~~**`OutpostManager`·`SettlementManager`를 런타임 레지스트리로.**~~ — **2026-08-27 완료.**

   `OutpostManager.Build`가 `WorldMap.SetContent(node, Outpost)`로 **저작 격자를 고치고
   있었다** — 플레이 중에 생기는 것을 저작물에 쓰는 일이고, 자리가 굽힌 에셋으로 오면서
   성립하지도 않게 됐다. 이제 **`OutpostManager.All`이 답한다.**

   - `WorldOutpost.Position`(월드 XZ)이 자리를 들고 **칸은 파생**. 한 지역에 하나라는
     제한이 없어져 **거리로 찾는다**(`At(pos, radius)`).
   - **`WorldBandManager.NearestMine`이 격자 4,096칸 전수 훑기를 그만뒀다** —
     `DungeonCore.All` + `OutpostManager.All`을 본다.
   - **습격 목표(`RaidPlan.Target`)가 월드 좌표가 됐다.** 칸으로는 가리킬 수가 없다
     (한 지역에 둘 이상 설 수 있으므로). `DeliverRaid`도 격자의 칸 내용물 대신
     레지스트리에 묻는다.
   - **지도 패널의 격자 훑기가 통째로 사라졌다** — 장소는 `WorldSites`, 채집기지는
     `OutpostManager.All`, 내 거점은 `DungeonCore.All`.
   - `SettlementManager.RegisterSettlement`는 그대로 둔다 — 그건 `WorldMap`의 **런타임
     목록**이지 저작 에셋(`mapData`)이 아니고, 옛 화면이 아직 읽는다.


# 세계 저작·장소 배치·남은 미결 — CLAUDE.md에서 내려온 원문 (2026-09-25)

CLAUDE.md를 절반 아래로 줄이며 옮겼다(사용자). **원문 그대로다** — CLAUDE.md에는 절마다 몇 줄과 포인터만 남았다.

**세계 저작은 씬에서 한다 — 저작 씬에 세계 전체가 서 있고 게임을 켜면 그것이 청크로 스트리밍된다**(2026-08-27 사용자 결정. **세부는 `docs/design_world_editor.md` — 에디터 1—4단계와 노드 걷어내기 네 단계 모두 완료, 남은 것은 퀘스트뿐이다**). 굽기가 `Resources/WorldContent/{x}_{y}.asset`을 내놓고(`TerrainDelta`와 같은 패턴 · 조회 O(1) · **없다는 사실도 기억한다** · `Persistent` 키는 **`Id`**) 도구는 `World → 3. Open Authoring Scene` / `4. Load World Into Scene` / `5. Bake World`다.

- **씬에 들어가는 것과 안 들어가는 것을 가르는 것이 이 설계의 전부다** — 저작한 물건과 조각한 청크는 들어가고, 안 조각한 지형(함수, 550MB)과 뿌리는 나무·바위(해시)는 안 들어간다. **지형이 없어도 되는 이유는 물건이 높이를 저장하지 않기 때문이다**(XZ + `YOffset`).
- **저작 씬은 빌드에 안 넣는다 — 다만 빼는 것만으로는 안 막힌다.** 에디터의 Play는 **열린 씬을 그대로 들고 들어가** 마을·소굴 수백 곳이 살아나고 **NPC가 지형 없는 허공에서 떨어지며** 스트리밍이 세운 것과 **두 벌**이 된다. 그래서 `WorldAuthoringRoot`가 **`Awake`에서 스스로 꺼진다.** **저작 루트는 `WorldAuthoring`, 스트리밍 루트는 `World`**(둘 다 `"World"`였을 때는 저작 루트에 스트리머가 붙어 **판이 열릴 때 세계가 통째로 안 섰다**) — **배선 도구는 이름보다 컴포넌트를 먼저 찾는다.**
- **청크 에셋에 쓰는 문은 `5. Bake World` 하나다** — 밖에서 에셋에 직접 쓰면 **저작 씬이 모르는 물건**이 되어 다음 굽기가 지워 버린다. **굽기는 지우기까지 하므로 씬이 세계 전부를 담았을 때만 돌린다**(`LoadedWholeWorld`, 없으면 거절 — 일부만 펼쳐 놓고 구우면 안 펼친 청크가 통째로 사라진다). **프리팹 인스턴스 안으로는 안 내려가고**(마을 하나가 수십 개로 쪼개진다) **복제하면 신원이 겹쳐** 새로 발급하며 **`TerrainStreamer`를 못 찾으면 거절한다**(기본 프로필로 `YOffset`을 재면 마을이 공중에 뜬다). **`5. Place Sites`는 신원으로 맞춘다**(둘 다 있으면 **그대로 둔다** — 손으로 민 자리가 유지된다 · 지도에만 있으면 세우고 · 씬에만 있으면 지운다 · **지도가 비었으면 아무것도 안 지우고 멈춘다**).
- **안 들어가는 것과 안 보이는 것은 다르다** — `WorldSceneTerrain`이 **에디터에서도 스트리밍을 돌려** 씬 뷰 카메라 둘레를 진짜 해상도로 세운다(`HideFlags.DontSave` · 떠나면 `TerrainData`까지 버린다 · `TerrainStreamer`가 없는 씬에서는 **아무것도 안 세운다**: 프로필 없이 세우면 **게임과 다른 땅**이 선다). **벽도 같이 선다 — 런타임과 같은 문**(`RockRenderer.OnTerrainChunk`)을 두드린다(따로 그리면 *에디터에서 보이는 벽*과 *게임에서 막는 벽*이 갈린다): 반경은 지형보다 좁고 · **에디터에는 프레임이 없어 `EditorFlush`가 대신 굽고**(예약만 해 두면 아무도 안 굽는다) · **자르기는 안 걸며**(게임 카메라 높이로 깎는 장치라 씬 뷰에서는 엉뚱한 데서 잘린다) · **버리는 문은 `Toss` 하나다**(`Destroy`는 편집 모드에서 에러, `DestroyImmediate`는 플레이 중 금지). **콜라이더를 단다**(프리팹을 끌어다 놓을 때 여기에 스냅된다).
- **에디터 틱은 게임이 도는 내내 함께 돈다**(`EditorApplication.update`) — 거기서 런타임 물건을 찾아 건드리면 **매 프레임 부순다**(2026-09-12에 바위가 그랬다: 씬 뷰에는 멀쩡한데 Play만 하면 `RockChunks`가 아예 없었다). **들어가기 직전에는 치우고 들어간 뒤에는 손도 대지 않는다 — 묻는 것은 `isPlaying`이지 `isPlayingOrWillChangePlaymode`가 아니다**(그 둘을 한 조건으로 묶은 것이 사고였다). **그리고 치우는 쪽이 제 목록으로 찾으면 안 된다**(2026-09-18) — **도메인 리로드가 바로 그 목록을 비운다**: 스크립트를 다시 컴파일하면 `_chunks`·`_root` 같은 순수 C# 필드는 날아가는데 **`HideFlags.DontSave`는 *저장 안 함*이지 *안 죽음*이라 오브젝트는 살아남는다**(씬을 다시 읽어도, 플레이에 들어가도). 그래서 **컴파일할 때마다 청크가 한 벌씩 쌓였고** `EditorClear`는 빈 목록을 돌며 아무것도 안 치웠다. 그 벌은 **굳은 시점의 지형을 콜라이더로 들고 있어** 그 뒤에 판 자리를 폰이 **보이지 않는 벽**으로 막혔다 (메시는 새 벌이 그리므로 **벽은 안 보인다** · 진단에 같은 범위의 낡은 박스가 **그날 컴파일한 횟수만큼** 찍힌다). **잃어버린 것이 목록이므로 메모리를 훑어 거둔다**(`RockRenderer.ReapStrayRoots` — 루트를 새로 세우는 자리와 `EditorClear` 둘 다에서). **씬 목록(`GetRootGameObjects`)으로 찾지 말 것**(2026-09-19) — 에디터가 `DontSave`로 세운 것은 플레이 사이에 **활성 씬 목록 밖**에 남을 수 있어, 그 판에는 *"거뒀다"*가 한 줄도 없이 낡은 박스가 두 벌씩 막았다. 답은 `Resources.FindObjectsOfTypeAll`(에셋은 뺀다). 증상이 *"원래 잘 됐는데 갑자기 판 자리로 못 간다"*라서 **최근 코드 변경을 아무리 뒤져도 안 나온다** — 원인이 코드가 아니라 **컴파일했다는 사실 자체**다. **같은 플래그가 반대쪽에서도 샌다** — 런타임에 `DontSave`로 만든 것은 **플레이를 나가도 에디터 씬에 그대로 남는다**(*"게임 씬이 씬에 남아 있다"*). **런타임 오브젝트의 플래그는 `SelfStanding.RuntimeObject`(= `DontSaveInEditor`) 하나다** — 바라는 것은 *저장만 안 됨*이지 *안 죽음*이 아니다. **에셋(`Material`·`Mesh`)은 예외로 `HideAndDontSave`를 그대로 쓴다**(거기서는 *안 쓰는 것으로 보고 버리지 마라*라는 뜻이다).
- **노드 걷어내기(별건, 네 단계 완료)** — 무리·소굴·마을이 `Vector2Int` 노드로 돌던 것을 좌표로 옮겼다. **노드가 답하던 물음은 셋**이고(주소 → `WorldObject.Id` · 자리 → `Position` · 이웃거리 → 좌표 직선거리) 새로 필요한 것은 **좌표 색인 `WorldSites`**였다(구운 청크를 **전부** 훑는다 — 지도가 세계 전체를 한 번에 그리고 무리는 안 가 본 곳의 마을도 알아야 한다). **`Kind == Empty`는 장소가 아니다**(넣으면 "가장 가까운 마을"이 바위를 짚는다) · **종류를 물건이 든다**(`WorldObject.Kind` — 전에는 저작 격자가 들어서 **손으로 놓은 마을이 게임 지도에 안 떴다**) · **소굴·상점·모집은 `Id` 키다**(전에는 **노드를 해시**해서 **마을을 200m 옮기면 재고와 후보가 통째로 달라졌다** — 자리를 다듬는 일이 뽑기가 됐다) · **`string.GetHashCode`를 안 쓴다**(실행마다 달라진다) · **칸은 자리에서 파생시킨다**(둘을 각자 들면 옮겼을 때 한쪽만 따라온다) · **친 소굴은 런타임 상태다**(`WorldLairs.IsGone` — 전에는 `SetContent(Empty)`로 **저작 격자를 고쳐서** 지웠다) · **전초기지도 레지스트리다**(`OutpostManager.All` — `NearestMine`의 격자 4,096칸 전수 훑기와 지도 패널의 격자 훑기가 통째로 사라졌다) · **습격 목표는 월드 좌표다**(한 지역에 둘 이상 설 수 있어 칸으로는 못 가리킨다) · **`BandMaterializer`는 `0. Setup World Streaming`이 붙인다**(없으면 토큰만 굴러 **무리가 영영 실제 폰이 안 된다**).


**장소 배치는 자동이다**(2026-08-27, 사용자 결정) — `Terrain → 5. Populate World`. 전에는 저작 격자 **한 칸에 하나씩**이라 개수가 *"몇 칸을 칠했나"*로 정해지고 한 지역에 하나뿐이었다. 이제 **격자는 바이옴만 든다.** **다트 던지기 + 최소 간격**(격자로 나누면 자로 잰 듯 늘어서고, 완전 무작위면 뭉친다) · **찍은 자리를 그대로 안 쓴다**(둘레에서 가장 평평한 데로 한 번 옮긴다 — 무작위로 찍으면 절반이 비탈이다) · **티어가 밀도를 정한다**(마을은 낮은 티어일수록 많고 **4티어 이상엔 안 선다** · 소굴은 높은 티어일수록 많다 — **자원은 여기서 안 놓는다**: 2026-09-14에 걷어냈고 바이옴이 답한다) · **시작 둘레는 비운다** · **시드 하나에서 전부 나온다.** **손으로 놓은 것(`Generated` 꺼짐)은 안 건드린다** — 그게 없으면 한 번 돌릴 때마다 손으로 지은 도시가 사라져 다시 돌릴 엄두가 안 난다.

**남은 미결은 둘이다**(2026-09-07에 *적도 능동을 쓰는가*가 닫혔다 — **`UseAbilityNode`**. 가르는 축은 **`UnitBrain.AbilityByHand` 하나**다 — *사람이 눌러 주는 폰인가*(= **내 세력**이고 **명령을 받는다**). **`AcceptsOrders` 하나로 가르면 안 된다** — 그건 *하수인 종족인가*라서 **적도 `UnitData`를 쓰니 참이 되고**, 그러면 **정작 적이 능동을 안 쓴다**(만들려던 것이 통째로 안 걸린다. `is MinionData`가 *"하수인 종족"이지 "내 편"이 아닌* 것과 **같은 함정**이고, 2026-09-07에 실제로 그렇게 짰다가 잡았다). **답은 실제로 누르는 경로에서 나온다** — `SelectionManager`가 플레이어 세력만 고르고 `AbilityController`가 거기서 명령 받는 폰만 남긴다. **하수인이 여기 걸리는 것이 요점** — 사람이 눌러 줄 길이 아예 없었다. **용병은 스스로 쓴다**(플레이어 세력이 아니라 고를 수가 없다 — 곁에서 알아서 싸우는 것이 그 계약의 뜻이다). **대형 무기를 든 로드아웃은 방패를 못 껴 도발도 없다**(`OffHandLocked`) — 산적두목·고블린 창병이 그렇다. *쓸 만한가*는 **능력의 주인이 답한다**(`Taunt.Worth` — `AbilityUser`에서 분기하면 능력이 늘 때마다 그 파일이 전투 규칙을 알게 된다). 도발의 규칙은 **끌어올 것이 하나라도 있으면 쓴다**(범위 안에 나를 안 보는 놈이 있나 — 다 나를 노리고 있으면 걸어도 안 바뀐다). **노드는 늘 성공을 돌려준다** — 전투 **앞**에 서므로 실패를 돌려주면 능력이 없다는 이유로 **싸움이 통째로 멎는다**. **`CanUse`를 `WorthUsing`보다 먼저 묻는다** — 뒤의 것이 둘레를 훑으므로 순서를 뒤집으면 싸우는 폰마다 매 틱 헛스캔이 붙는다) — 월드맵의 **`직접 건설`**(`design_world_field`, 필드맵 절차 생성이 필요해 덩치가 크다) · **월드 에디터**(`design_world_editor`, 저작 씬에 세계 전체를 두고 굽는다 — **에디터 1—4단계와 노드 걷어내기 네 단계 모두 완료**. 남은 것은 퀴스트뿐이다). **스탯 창은 안 든 장비의 숙련도 그대로 띄운다**(2026-08-26) — 숨기는 기준을 *지금 그 장비를 들었나*로 잡으면 활·지팡이·제작이 전부 같은 처지라 **폰마다 창 모양이 달라져 비교가 안 되고**, 무엇보다 *"이 폰에게 무엇을 쥐여 줄까"*를 정하려면 **안 든 지금** 보여야 한다. **"구현 예정"이라고 적어 두면 다음에 읽는 사람이 이미 끝난 것을 다시 잰다.**

**이 파일에는 150,000자 한도가 있다 — 넘으면 뒤가 잘려 나가고, 잘린 줄은 아무도 못 읽는다.** 그러니 **여기 남는 것은 "밖에서 어기기 쉬운 것"뿐이다**: 답이 한 벌이어야 하는 자리 · 빠뜨리면 조용히 틀리는 것 · 왜 그렇게 정했는지의 한 줄. 한 축의 세부(눈금·저작 목록·화면 규격·겪은 사고의 전말)는 **`docs/`로 내리고 여기에는 포인터를 남긴다.** 기준: **표·API 목록·단축키·"어기면 조용히 틀리는 한 줄"은 여기, 눈금과 저작 목록과 겪은 사고의 전말은 저기.** 세 번 내렸다 — 2026-08-27에 155,092자로 **넘겨서** 107,000자를 내렸고(47,844자로), **2026-09-13에 136,112 → 116,422로**(91% → 78%), **2026-09-25에 144,112 → 116,031로**(96% → 77% — 파일 앞쪽의 *최근 결정* 대목들을 원문 그대로 각 `docs/` 끝의 *"CLAUDE.md에서 내려온 원문 (2026-09-25)"* 절로 옮기고 여기는 규칙만 남겼다). **두 번째는 넘기기 전에 했고, 그래서 고른 것이 달랐다**: 넘친 뒤에는 *무엇을 버릴까*를 고르지만 미리 하면 *어디가 두 벌인가*를 고르게 된다 — 실제로 줄어든 것의 절반이 **docs에 이미 있던 중복**이었다(습격대·굴 생성·밤·버섯). **내릴 때는 지우지 말고 옮길 것** — 09-13에 옮긴 원문은 `docs/`의 *"CLAUDE.md에서 내려온 상세"* 절들이고, **압축하며 지운 줄이 docs 어디에도 없는지 굵은 어구로 훑어 확인했다**(그때 `World → 7. Create Mushrooms`가 양쪽에서 사라진 것이 잡혔다). **그리고 내리면서 낡은 줄이 드러난다** — 옮겨 붙일 자리를 읽다가 docs 쪽이 *"주기는 세계 크기에 매인다"*(08-31에 뒤집힌 규칙)와 *"밤 이름은 미결"*(이미 정해졌다)을 아직 말하고 있었고, CLAUDE.md 안에서도 **세계 크기가 두 곳에서 서로 다른 말**(1,024m ↔ 4,096m)을 하고 있었다. **길이는 글자로 잰다** — `python -c "print(len(open('CLAUDE.md',encoding='utf-8').read()))"`. `wc -c`도, 로케일이 UTF-8이 아닌 셸의 `wc -m`도 **바이트를 세어 한글을 세 배로 부풀린다**(둘 다 29만이라고 답한다).

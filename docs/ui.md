# UI System

## 캔버스 그리기 순서 (2026-08-14)

**`Canvas` 직속 자식의 순서가 곧 그리기 순서다** — 뒤에 있을수록 위에 그려진다. 그게 어긋나 있어서
상점에서 아이템 툴팁이 창 뒤로 가고, 대화창의 막힌 줄에 마우스를 올려도 설명이 안 보였다.
쌓는 순서는 **아래에서 위로 다섯 층**:

| 층 | 무엇 | 왜 |
|---|---|---|
| 1. 상시 HUD | `PawnRoster` · `Time` · `Inspect` | 늘 떠 있으므로 창이 덮어도 된다 |
| 2. 패널 | `ResourceNode` · `Storage` · `PatrolZone` · `Farm` · `CraftingTable` · `ResearchTable` · `DungeonCore` · `UnitStats` · `Colony` · `Expedition` · `BuildMode` · `WorldUI` | 서로 겹칠 일이 드물다 |
| 3. 거래 묶음 | `Merchant` → `CorpseInventory` → `Inventory` | **끌어다 놓는 쪽이 위** — 배낭에서 상점으로 드래그한다 |
| 4. 대화·팝업 | `Dialogue` · `FactionPanel` · `PawnContextMenu` | 무언가를 고르는 창이라 패널보다 위 |
| 5. 알림·툴팁 | `EventNotification` → `ItemInfo` → `HoverTooltip` | **커서를 따라다니는 것은 무엇에도 안 가려야 한다** |

**새 UI를 씬에 더할 때는 이 순서에 끼워 넣을 것** — 맨 뒤에 붙이면 툴팁 위에 그려진다.

## 무엇을 매 프레임 갱신할 것인가

| | 예 | 방법 |
|---|---|---|
| **시간에 따라 연속으로 변함** | 연료 게이지, 제작 진행률 | `Update`에서 매 프레임. 이벤트만 쓰면 게이지가 시작·끝에만 툭 움직여 "돌고 있다"가 안 읽힌다 |
| **사건이 있을 때만 변함** | 재고 수량, `최대 8`, 배정 목록 | **이벤트 구독** — `Storage.OnChanged`(static) · `Inventory.OnChanged` · `CraftingTable.OnChanged` · `ResourceNode.OnAssignmentChanged` |

매 프레임 하면 비싼 것 세 가지: **목록 재생성**(`Instantiate`/`Destroy` → GC + 레이아웃 재계산),

**TMP 대입**(문자열 할당 + **같은 값을 넣어도 메시를 다시 굽는다**).

> **매 프레임 도는 자리에서 TMP에 글자를 넣을 때는 값이 바뀌었는지 먼저 본다.**
> `CraftingTableUI.SetText(label, value)`가 그 한 줄이다 — 진행률처럼 실제로 매 프레임 도는
> 곳에서도 글자가 그대로면 아무 일도 하지 않는다.

**공통 패턴:**
- **캔버스는 하나** — 필드 UI와 월드 UI가 같은 Canvas 아래 형제로 산다. 모드 전환(`GameModeManager`)은 캔버스가 아니라 **캔버스의 직속 자식들**을 다루고, 월드 전용 묶음(`WorldUI`)만 반대로 켠다. 그래서 **월드 전용 UI는 반드시 `Canvas/WorldUI` 바로 아래**에 둘 것 — 더 깊이 넣거나 밖에 두면 필드 UI와 같이 꺼진다
- **필드 UI는 "일괄 on/off"가 아니라 상태 복원** — 월드로 나갈 때 열려 있던 패널을 기억했다가 돌아올 때 그대로 되돌린다(`GameModeManager.ApplyFieldUi`). 일괄로 켜면 **닫아 뒀던 인벤토리·상점 패널까지 따라 열린다**
- **양쪽 모드에서 다 쓰는 창은 스태시에서 뺀다** — 상점·배낭·툴팁(`MerchantUI`·`InventoryUI`·`ItemInfoUI`)이 그렇다. 거래는 거점 상인에게도 하고 월드맵 마을에서도 하는데, 필드 UI로 묶여 있으면 지도에서 여는 순간 꺼진다. 목록은 **씬 배열이 아니라** 컴포넌트에서 캔버스 직속 부모를 타고 올라가 찾는다(`GameModeManager.CollectModeAgnosticUi`) — 인스펙터에 적으면 새 창을 만들 때마다 배선을 빠뜨린다. 스태시에서 빼는 것뿐이라 **알아서 열리지는 않는다**(늘 켠 루트 + 꺼지는 `panel` 자식 구조라서)
- `BuildModeManager.OnActiveChanged` — 건설 모드 열릴 때 대부분 UI 자동 닫힘
- `CloseButton` — `Target` RectTransform 연결 시 클릭으로 비활성화
- ESC 키 — 대부분 패널이 `Update()`에서 `escapeKey.wasPressedThisFrame` 체크로 닫힘
- 마우스 휠 — 커서가 UI 위면 `CameraController`가 줌을 건너뛴다(패널 스크롤 우선). 클릭 게이트와 같은 `EventSystem.IsPointerOverGameObject` 방식

## InventoryGridUI

그리드 시각화. 다중 컨테이너 드래그-드롭 지원.

- `_activeGrids` 정적 목록 — 열린 모든 그리드 추적
- `ReceiveFilter: Func<ItemData, bool>` — 외부 필터 주입 (Storage는 `CanAccept` 연결)
- `FindUnderCursor(screenPos, cam)` — 현재 커서 아래 그리드 반환
- `ShowPreview(inst, x, y, rotated, isExternal)` — 초록/빨강 오버레이 색 피드백
- `ClearPreview()` — 프리뷰 초기화
- `ScreenToGrid(screenPos)` — `_itemsRoot` (pivot 0,1) 기준 그리드 좌표 변환

## DraggableItem

아이콘 자동 추가. 드래그/드롭/회전 처리.

- **Q/E — 90° 회전**(`localRotation = Euler(0,0,-90°)` + 셀 점유 변경). **건설 모드가 고스트를
  돌리는 키와 같다**(`BuildModeManager`) — 둘은 같이 켜지지 않으므로 겹치지 않고, 손이 한 번
  배우면 두 곳에서 통한다. 격자 회전은 상태가 둘뿐이라 Q와 E가 같은 일을 한다.
- **회전은 `Update`가 받는다 — `OnDrag`가 아니라.** `IDragHandler.OnDrag`는 **포인터가 움직인
  프레임에만** 불려서, 마우스를 가만히 둔 채 누른 키는 그대로 사라진다(`wasPressedThisFrame`은
  한 프레임짜리다). 증상은 *"한 번 돌리고 나면 마우스를 움직여야 다시 돌아간다"*였다.
- **손에 든 것은 크기만 맞바꾼다 — 트랜스폼은 안 돌린다.** 둘을 같이 하면 **두 번 돌아** 원래
  방향으로 보이고, 피벗이 좌상단이라 회전이 상자를 커서 옆으로 던진다. 크기만 바꾸면 손에 든
  것이 곧 발자국이라 미리보기와 정확히 겹친다(그림은 `preserveAspect`가 지킨다).
- **놓일 칸은 `InventoryGridUI.PlacementCell` 하나가 답한다** — 미리보기·실제 놓기·장비칸 드래그가
  같이 쓴다. 각자 `cursorCell - grab`을 쓰던 시절엔 가장자리에서 **격자 밖에 밝은 칸이 그려지고**
  실제로는 딴 자리에 놓였다. 격자 안쪽으로 당기므로 가장자리에 걸친 드롭도 그냥 된다.
- **끌지 않고도 돌린다** — 아이템에 커서를 얹고 Q/E(`InventoryGridUI.Update` → `Inventory.RotateItem`).
  예전엔 드래그 중에만 돌아서 **시스템은 있는데 꺼낼 길이 없었다**(1×3을 눕히려면 일단 집어야
  했는데, 보통은 자리를 보고 나서 돌리고 싶다). **커서 아래를 누를 때 그때그때 찾는다** —
  얹힘을 상태로 들면 돌릴 때 아이콘이 다시 만들어지며 그 상태가 끊겨 **두 번째 Q가 안 먹는다**
  (`OnPointerExit`는 파괴될 때 안 온다). 격자를 벗어나면 **안쪽으로 당겨서** 돌린다 —
  가장자리 물건이 영영 못 도는 것을 막는다(자리가 좁아 돌리려는 건데 좁다고 거절하는 꼴이다).
- **드래그가 아니라 집기/놓기다**(2026-08-19). 좌클릭으로 집고(Shift=절반 / Ctrl=하나) 좌클릭으로 놓는다 — 드래그로는 **교체가 성립하지 않는다**(A를 B 위에 놓으면 B가 손에 들려야 하는데 버튼을 떼는 순간 끝난다). `IDropHandler`·`DropHandled`·더블클릭은 그때 전부 없앴다.
- 놓을 곳을 묻는 순서(`DraggableItem.EndCarry`): **장비칸 → 격자 → 판매 구역 → 바닥**. 배낭 격자가 장비 열까지 덮고 있어 격자를 먼저 물으면 착용이 아예 안 된다
- 같은 그리드 안 = `MoveItem`, 다른 그리드 = `TryAddAt` + `RemoveInstance`, UI 밖 = `DroppedItem.Spawn`
- **못 놓으면 손을 안 턴다** — 계속 들고 짧게 흔든다
- `CanReceiveItem` 체크로 ReceiveFilter 적용. 색 피드백: 초록(가능)/빨강(불가)

## EquipSlotUI

장착 슬롯 1칸. `Equipment.OnEquipChanged` 이벤트를 내부에서 직접 구독하는 자기관리형 컴포넌트.

- `Init(SlotKind)` — 슬롯 종류(MainHand/OffHand/Head/Chest/Hands/Legs) 설정
- `Bind(Equipment)` — Equipment 교체 시 이벤트 재구독 + Refresh
- **좌클릭=집는다**(벗기와 집기가 한 동작) / **손에 들고 좌클릭=찬다**(차던 것이 손에 들린다) / **우클릭=벗어서 배낭으로**
- 호버 → `ItemInfoUI` 툴팁

### 창은 "늘 켜진 부모 + 꺼지는 자식"으로 짓는다

**창 컴포넌트는 전부 `XxxUI`이고, 씬 오브젝트는 `Xxx_UI`(부모) / `Xxx_Panel`(자식)이다**
(2026-08-04 통일 — `docs/editor_creators.md` "창 오브젝트 이름 규약").
`EventNotificationUI` · `MerchantUI` · `InventoryUI` · `ItemInfoUI` 전부 이 꼴이다 —
컴포넌트는 **늘 켜져 있는** 오브젝트에 살고, 보였다 사라지는 건 `[SerializeField] GameObject panel`이다.

**컴포넌트를 꺼지는 그 오브젝트에 붙이면 안 된다.** 유니티는 꺼진 오브젝트의 `Awake`를 부르지
않으므로 `Instance`가 영영 null이 되고, static 진입점(`Show`/`Notify`)이 조용히 아무것도 안 한다.
`ItemInfoUI`가 정확히 그래서 **툴팁이 한 번도 안 떴다**(2026-08-04 발견).

런타임 `FindObjectsInactive.Include`로 때울 수도 있지만 쓰지 않는다 — hover마다 도는 경로에

구조를 고치던 `Fix Window Structure` 도구는 다 쓰고 지웠다(2026-08-06) — 이후는 인스펙터에서

## UI를 고치는 방법

**UI 생성기는 남아 있지 않다.** 패널·프리팹은 이미 씬/에셋에 지어져 있고, **모양 수정은 인스펙터에서** 한다(생성기의 수명과 판단 기준은 `docs/editor_creators.md` "생성기의 수명 — 다 쓰면 지운다").

- 반복 항목(명부 행, 상점 재고 행 등)은 **씬 템플릿 또는 프리팹을 복제**해 채운다 — 여백·폰트·색·크기는 그 오브젝트가 갖고 코드는 데이터만 넣는다.
- 처음부터 다시 지어야 하면 git 이력에서 해당 생성기를 꺼내 쓴다.
- 지금 남아 있는 에디터 도구 목록은 `docs/editor_creators.md`의 "남아 있는 도구" 절.

## 상점·인벤토리 조작

(CLAUDE.md의 `상인 시스템`에서 옮겨 왔다 — 규칙 요약은 그쪽에, 세부는 여기.)

**UI 구조:**
- `MerchantUI` ← `Merchant.OnSelected` 이벤트로 오픈. 상인 재고(구매)만 담당.
  - **재고 보기는 둘이고 오간다**(`StockView`, 재고 줄 우측 버튼 — 글자는 **누르면 갈 곳**). 하나로 못 정하는 것은 재고를 보는 목적이 둘이기 때문이다: *"뭘 파나"* 훑을 때와 *"어떤 물건인가"* 들여다볼 때 원하는 화면이 다르다.
    - **칸**(기본) — **배낭과 똑같은 격자**다. 흉내가 아니라 재고를 진짜 `Inventory`로 만들어 `InventoryGridUI`가 그린다(`ReadOnly`). 그래야 **2×4 갑옷이 자리를 얼마나 먹는지 사기 전에 보인다** — 카드는 그걸 못 보여 주고, 그리는 코드를 두 벌로 두면 언젠가 어긋난다. 값·이름·등급은 **툴팁과 아래 구매 줄**이 답한다.
    - **카드** — 96×112 타일에 그림·이름·등급·값·재고가 같이(`tileEntryPrefab`, 비우면 이 보기가 꺼진다).
  - **창 크기는 씬이 정한다**(`Merchant_Panel` 580×700 — 8×10 격자 × 64px 중 아홉 줄이 보이고 나머지는 스크롤). **코드가 격자에 맞춰 창을 늘리지 않는다** — *모양·자리의 정본은 씬*이라, 덮어쓰면 인스펙터에서 맞춰도 실행하면 딴 크기가 된다. **진열대를 키우면(`StockGrid`) 창도 같이 키울 것.**
  - **좌판은 진짜 격자다 — 자리가 곧 판매 한도다**(`Shop.Stall`, `Inventory`). 자리를 두면 셋이 한꺼번에 선다: **칸이 차면 더 못 판다**(한 마을에 다 쏟아붓지 못하고 돌아다닐 이유가 생긴다) · **판 물건이 좌판에 오른다**(도로 살 수 있다 — **판 값 그대로**) · **갱신 때 상인의 제 물건이 자리를 먼저 가진다**(`Refresh`가 굴림표를 먼저 놓고 내가 맡긴 것을 남은 자리에 놓는다 — **밀려난 것은 사라진다**).
    - **한도는 `Shop`이 든다 — 화면이 아니라.** 격자를 상점 창이 만들면 "몇 개까지 팔리나"를 창이 정하는 꼴이라 창을 안 열고 파는 길이 생기면 규칙이 샌다. `MerchantUI`는 `Stall`을 **보여 주기만** 한다.
    - **자리 판정은 `CanFit`이 아니라 `TryAdd`의 결과다.** `CanFit`은 빈 칸을 **넓이로만** 세서 조각남을 못 본다(스스로 "후하게 나올 수 있다"고 적어 둔 판정이다) — 빈 칸 여덟이 뿔뿔이 흩어져 있으면 2×4 갑옷에게 "된다"고 답하고, 그 말을 믿고 값을 치른 뒤 `TryAdd`가 조용히 실패해 **판 물건이 세상에서 사라졌다**(2026-08-15 수정: 좌판이 꽉 찬 것처럼 보여도 판매가 안 막히던 증상의 정체). 넣어 보고 그 답을 쓰되, 뒤에서 대금·출고가 틀어지면 **좌판에 얹은 것도 도로 내린다**. `HasRoomFor`는 UI가 "왜 안 되는지" 물을 때만 쓴다.
    - **칸 정리**(`Inventory.Compact` — 상점 `[정리]`·배낭 `[정리]`): 같은 것끼리 합치고 **큰 것부터** 위에서부터 다시 채워 넣는다. 격자는 쓰다 보면 반드시 조각나는데 여기서는 그게 **판매 한도로 직결된다**(칸 수는 넉넉한데 연속된 자리가 없어 거절당한다). 좌판은 손으로도 옮길 수 있지만(아래) 한 번에 푸는 길이 없으면 조각난 좌판을 손으로 되짚는 잡일이 된다. 잠금은 **하나라도 잠겨 있으면 합친 뭉치가 잠긴다**(합치다 풀리면 자동 운반이 조용히 집어 간다).
    - **좌판이 물리적 진실, `Stock` 목록은 값표다.** `SyncStall`이 목록을 좌판에 옮겨 담고 **안 들어간 것은 목록에서도 뺀다** — 둘이 어긋나면 "화면엔 있는데 못 산다"가 된다.
    - **좌판은 그 사람의 가게다 — 갱신 때 상인의 제 물건이 먼저 자리를 가진다.** 순서가 곧 우선권이고(`SyncStall`이 목록 순서대로 놓고 자리가 없으면 뺀다) 굴림표가 앞에 온다. 반대로 두면 **좌판을 내 물건으로 채우는 것만으로 그 상인의 새 물건이 줄어든다** — 무기 상인에게 빵을 팔았다고 다음 날 검이 덜 들어오는 꼴이라, 상인의 성격이 내가 뭘 떠넘겼느냐로 흔들린다. **밀려난 것은 사라진다**(상인이 어딘가로 넘겼다고 본다): 값은 이미 받았으니 잃는 것은 *되살 기회*뿐이고, **그것이 한 상인에게 몰아 파는 것의 대가**다.
    - **되사는 값은 판 값 그대로다 — 판 순간에 얼어붙는다**(`AddPlayerStock`이 받은 액수를 그대로 적어 둔다). 되팔이 값(기준가 × 등급 × 지역배율)을 붙이면 방금 판 검을 도로 사는 데 **네 배 가까이** 들어 **잘못 판 것을 무를 길이 없다.** 얼려 두는 것은 안전장치이기도 하다: `Reprice`가 이 항목을 건드리면 **판 값보다 싸게 되사게 되어 돈이 찍힌다**(사교 130이면 팔 때 +18% 살 때 −18%라 왕복에 3할이 남는다). 그래서 `Reprice`는 `FromPlayer`를 건너뛰고, **되사기에는 사교 성장도 안 붙는다**(왕복이 손익 0이라 안 막으면 공짜로 스탯을 올린다).
    - **같은 돈으로 두 번 배우지 않는다**(`Shop.TeachableGold`) — 되사기 성장을 막아도 *팔고 → 되사고 → 다시 파는* 고리는 매도 성장을 계속 준다. **상한은 안 둔다**(그러면 그 위로는 아무리 팔아도 안 늘어 "돈을 쏟아부으면 오른다"는 축의 뜻이 사라진다). 대신 **이 상인이 나에게 *순수하게* 내준 돈**만 센다: 팔면 늘고 되사면 그만큼 돌아가며(`ReturnGold`), 이미 배움으로 친 액수를 넘어선 만큼에만 성장이 붙는다 → 왕복은 **두 번째부터 아무것도 안 주고**, 새 물건을 계속 팔면 **천장 없이 배운다**. 물건에 "되산 것" 표식을 달면 뭉치가 합쳐지고 쪼개질 때 그 행방을 정해야 하지만 **돈은 합쳐지고 쪼개져도 액수가 그대로**라 셈이 안 흔들린다. 뭉치에 더 얹어도 **처음 값을 지킨다** — 한 뭉치에 값이 둘일 수 없는데 나중 값으로 덮으면 하나 더 파는 것만으로 먼저 판 것의 되사기 값이 흔들린다.
    - **내가 판 물건은 `PlayerStockDays`(기본 7일)** 동안 남는다. 상인의 제 물건처럼 매일 갈리면 **좌판이 매일 아침 비어** 자리 한도가 아무것도 막지 못하고, 어제 판 것을 되사러 갈 수도 없다. 기한이 지나면 팔린 것으로 친다. **상인의 제 물건과는 안 합친다**(합치면 하루 뒤 굴림표와 함께 내 물건까지 사라진다).
    - 못 파는 이유는 **셋이고 할 일이 다 다르다** — `판매 불가`(값이 0) / `상인의 돈이 모자란다`(내일 다시 오거나 그에게서 사 준다) / `좌판에 자리가 없다`(다른 마을로 간다). 배낭 창 판매 줄과 판매 구역 알림이 같은 답을 쓴다.
  - **칸 수는 상인이, 칸 크기는 화면이 정한다.** 진열대가 몇 칸인지는 **`MerchantData.StockGrid`**(비우면 **폰 배낭과 같은 8×10** — 상인마다 따로 저작하라는 뜻이지 배낭과 달라야 한다는 뜻이 아니다) — 봇짐장수의 좌판과 큰 상단의 창고가 같을 이유가 없다. **폰 배낭 크기를 베끼지 않는다**: 그러면 진열대 크기가 *지금 누구 배낭을 보고 있느냐*로 바뀌어, 순환 버튼으로 폰을 넘길 때마다 좌판이 늘었다 줄었다 한다. 기본값이 8×10(배낭 기본)이던 것도 8×6으로 줄였다 — 물건 대여섯 개짜리 좌판에 **빈 칸이 여든 개**였고 창이 그만큼 커졌다. 반대로 **칸의 픽셀 크기는 배낭에서 베낀다**(`InventoryGridUI.CopyCellSize`, 열 때마다) — 그건 상인의 성질이 아니라 화면의 눈금이고, 나란히 뜬 두 격자의 눈금이 다르면 "이게 저기 들어가나"를 눈으로 못 잰다. **다 안 들어가는 날엔 줄만 늘린다** — 조용히 몇 개를 삼키면 어제 있던 물건이 왜 안 보이는지 알 길이 없다.
  - **진열도 끌 수 있다 — 다만 격자를 건너가면 이동이 아니라 거래다**(`InventoryGridUI.IsShop` → `DraggableItem.TryPlace` → `MerchantUI.HandleDragTrade`). 안 붙이면(`ReadOnly`) **좌판을 정리할 길이 없다** — 1×8로 남은 틈에 2×2를 넣으려면 1×1을 옆으로 밀어야 한다.
    - **좌판 안에서 옮기는 것은 그냥 이동**(정리), **좌판 → 배낭은 구매**, **배낭 → 좌판은 판매**. 합치기(`TryMerge`)보다 **먼저** 갈라야 한다 — 배낭 화살을 좌판 화살 위에 떨구면 그쪽이 먼저 걸려 값도 안 받고 넘어간다.
    - **좌판 것은 창 밖으로 못 꺼낸다**(`TryWorldDrop`) — 값도 안 치르고 땅에 떨구는 길이 된다. `FindCounterpart`에서도 여전히 빠진다(우클릭 "반대편으로 보내기"가 공짜 증여가 되면 안 된다).
    - **쪼개기는 다른 격자와 똑같다**(그냥=전부 / Shift=절반 / Ctrl=하나). **규칙이 하나 다르면 그것만 따로 외워야 한다.** 대신 진열에서는 **갈라 나온 조각을 좌판에 안 놓고 손에 든다**(`_detached` 갈래를 항상 탄다): 좌판에 갈라 놓으면 값표(`Shop.Stock`)의 한 줄이 좌판의 두 뭉치를 가리켜 사는 쪽에서 어느 것을 뺄지가 흐려진다. 손에 들면 좌판에서는 **그만큼 줄어든 것**일 뿐이다.
    - **살 때 손에 든 조각을 좌판에 되돌려 놓고 판다**(`HandleCarryTrade`). "이미 나와 있으니 좌판에서는 빼지 말라"는 예외를 `Shop`에 만들면 **사는 문 셋 중 하나만 다른 규칙**을 타게 된다. 되돌리기는 반드시 성공한다 — 갈라져 나온 뭉치가 좌판에 그대로 있어 `TryAdd`가 거기 합친다(새 칸을 안 먹는다). 그리고 **되돌린 이상 그 놓기는 끝난 것으로 친다**(실패해도 `true`) — 미배치로 돌리면 `EndCarry`가 손에 든 것을 한 번 더 좌판에 넣어 개수가 는다.
    - **좌판에서 집어 든 것은 장비칸에도, 판매 구역에도 안 들어간다**(`EquipSlotUI.TryEquipCarried`·`TrySellDrop`) — 각각 공짜 착용과 엉뚱한 "판매 실패" 알림이 된다.
  - **상점이 열려 있으면 우클릭 = 사고팔기**(`MerchantUI.HandleRightClick`). 배낭↔창고의 *"우클릭 = 이걸 저기로"* 규칙 그대로고 **"저기"가 상점일 뿐**이다 — 진열에서 누르면 사고 배낭에서 누르면 판다. 수량은 **집기 쪼개기와 같은 조합키**(`DraggableItem.ModifierAmount` — 그냥=전부 / Shift=절반 / Ctrl=하나): 같은 창에서 같은 키가 다른 뜻이면 손이 매번 확인해야 한다. **되든 안 되든 처리한 것으로 친다** — 실패했다고 평소의 "반대편 통으로 보내기"로 흘러가면 못 판 물건이 창고로 뛰어간다.
  - **어느 뭉치가 어느 재고 줄인가는 표를 안 만들고 그때그때 찾는다**(`EntryFor`) — 같은 물건·같은 등급이 두 줄이면 통에서 한 뭉치로 합쳐지는데, 표로 굳히면 그중 하나가 미아가 된다. 재고 남은 첫 줄을 고르므로 앞줄이 다 팔리면 저절로 다음 줄로 넘어간다.
  - **반대로 값표 한 줄이 좌판의 여러 뭉치를 덮기도 한다**(손으로 갈라 놓았을 때). 그래서 사는 쪽은 **줄이 아니라 누른 뭉치**를 본다: 살 수 있는 최대가 그 뭉치를 못 넘고(`MaxBuyable`이 `_selectedStack`을 같이 잰다), 줄어드는 것도 **그 뭉치부터**다(`TakeFromStall(prefer)`). 안 그러면 3+4로 갈라 둔 것을 3 쪽에서 우클릭했을 때 **일곱이 팔려 나가고**, 1개짜리를 눌러도 **옆의 5개가 줄어든다**. 갈라 놓았어도 값·기한·출처가 같으니 **줄은 하나가 맞다** — 줄까지 쪼개면 같은 물건이 같은 값으로 두 번 적힌다.
  - 진열용 통은 **꺼진 GameObject 하나**가 든다(`Inventory`가 MonoBehaviour라 어딘가엔 붙어야 하는데, 세상에 있는 통이 아니라 화면에만 있는 것이다). 높이는 **다 들어가는 최소로** 늘린다 — 재고는 날마다 다르고 갑옷은 넉 줄을 먹어서, 고정 높이면 어떤 날은 물건이 잘려 안 보인다.
  - 아이템 클릭/더블클릭 → 구매. 단건 구매만 지원.
**격자 조작은 "한 번 눌러 집고, 한 번 눌러 놓는다"** (2026-08-19, `DraggableItem`). **드래그가 아니다** — 교체가 드래그 안에서 성립하지 않는다: A를 B 위에 놓으면 B가 손에 들려야 하는데 드래그는 **버튼을 떼는 순간 끝난다.** **놓는 규칙(`TryPlace`)은 격자·장비칸·상인 창·판매 구역·바닥 모두 그대로다.**

| | 손이 비었을 때 | 손에 들었을 때 |
|---|---|---|
| **좌클릭** | **집는다**(Shift=절반 / Ctrl=하나 / 그냥=전부) · 집는 것이 곧 고르는 것이다 | **놓는다** — 발자국에 걸리는 것이 **하나면 그것이 손에 들리고**(교체), **둘 이상이면 아무 일도 안 일어난다** |
| **우클릭** | 이걸 저기로(반대편 통 · 착용 · **먹기** · 사고팔기 · 동전 회수) | **되돌린다** |
| **Q/E** | 커서 아래 뭉치를 돌린다(`InventoryGridUI.Update`) | 손에 든 것을 돌린다 |

- **더블클릭은 없앴다** — 첫 클릭이 이미 집으므로 두 번째를 기다릴 수가 없다. 그것이 하던 일(동전 회수 · 즉시 구매 · 즉시 판매)은 **우클릭이 이미 같은 자리에서 한다**.
- **잠금 모드에서는 클릭이 자물쇠다** — 집기보다 **먼저** 물어본다(`InventoryUI.ClickConsumed`). 안 물으면 잠그려다 물건이 손에 들린다.
- **손에 들고 있으면 그 클릭은 인벤토리의 것이다** — `SelectionManager`·`MoveController`가 물러난다. 안 막으면 창 밖을 누르는 한 번이 **물건을 떨구면서 폰까지 움직인다**.
- **창이 닫히면 손에 든 것을 되돌린다**(`Update`의 안전망) — 격자에서도 빠지고 화면에도 없는 물건이 남으면 개수가 조용히 샌다.
- **못 놓으면 손을 안 턴다 — 계속 들고 짧게 흔든다**(`EndCarry`). 실패하는 흔한 이유는 둘에 걸쳤다·자리가 없다인데, 그때 사람은 조금 옮겨 다시 누르려는 참이다. **바닥 드롭은 격자 밖에서만** — `IsPointerOverGameObject`는 레이캐스트에 걸리는 그림이 있어야 참이라 **빈 칸 위에서 거짓**이 나온다(그래서 못 놓은 물건이 땅에 떨어졌다). `FindUnderCursor`로 한 번 더 확인한다.
- **커서는 물건의 한가운데를 쥔다**(`GrabAtCenter`) — 좌상단을 쥐면 물건이 커서 오른쪽 아래에 통째로 깔려 **커서와 설명이 그림을 가린다**. 칸 오프셋과 픽셀 오프셋이 **같은 곳**을 가리켜야 손에 든 그림과 미리보기가 안 어긋난다(짝수 폭은 한가운데가 칸 경계라 오른쪽·아래 칸으로 친다 = `w / 2`).
- **손에 드는 순간 앵커를 캔버스 한가운데로 옮긴다**(`CenterAnchor`) — `커서로컬`(`ScreenPointToLocalPointInRectangle`)과 `anchoredPosition`의 **기준을 맞춰 버리면** 둘의 차이(화면 절반)를 이고 다닐 필요가 없다. 그 항 때문에 아이콘이 구석에 뜨거나(0으로 뒀을 때) 화면 밖으로 날아갔다(다시 재서 덮었을 때). 격자의 자식이 아니게 된 이상 앵커가 좌상단일 이유도 없다.
- **찬 만큼 손에서 덜어야 한다** — 손에 든 것은 **통에서 빠져 있지 않다**(격자가 안 그릴 뿐이다. 그래야 놓기에 실패해도 제자리에 그대로 있다). 그래서 장비칸이 받아 갈 때 `RemoveInstance`/`Quantity--`를 안 하면 **장비칸에도 있고 배낭에도 있는** 같은 물건이 둘이 된다.
- **놓을 곳은 장비칸을 먼저 묻는다**(`EndCarry`: 장비칸 → 격자 → 판매 구역 → 바닥) — **배낭 격자의 `RectTransform`이 장비 열까지 덮고 있어서**, 격자를 먼저 물으면 장비칸 위에 놓아도 배낭에 떨어져 **착용이 아예 안 된다**.
- **겹친 격자는 맨 위에 그려진 것이 이긴다**(`FindUnderCursor` — 공통 조상에서의 형제 번호). 먼저 걸리는 것을 쓰면 **등록 순서**(= 창을 연 순서)가 눈에 보이는 창을 이겨, 배낭에 놓은 물건이 뒤의 창고로 들어간다.
- **아이콘의 글자(이름·개수·잠금)는 `InventoryGridUI.Decorate` 하나가 붙인다** — 격자 아이콘과 손에 든 아이콘이 같은 것을 쓴다. 손에서 개수만 고치려고 첫 글자 자식을 집으면 **그림 없는 물건의 이름을 덮어쓴다**(개수가 1이면 빈 글자라 이름이 사라진다).
- **밀어낸 것은 통에서 빠져 손에 들린다**(`Inventory.TryPlaceOverAt`) — 자리를 맞바꾸지 않는 이유는 크기가 다르면 상대가 내 자리에 못 들어가는 일이 흔해서다. 손에 들면 **어디에 놓을지는 사람이 정한다.**

- `InventoryUI` — 상인 열림 시 판매 모드 전환. 하단 액션 바에 [판매] 버튼 표시.
  - 아이템 좌클릭 → **집는다**(집는 것이 곧 고르는 것이다 — 액션 바의 [판매]가 손에 든 것을 가리킨다), 판매 구역에 놓으면 판매. **더블클릭은 없다**(첫 클릭이 이미 집으므로 두 번째를 기다릴 수 없다 — 그것이 하던 일은 전부 우클릭이 한다)
  - **우클릭 = 한 번에 보내기.** 뜻은 **무엇이 열려 있느냐**가 정한다 — 반대편 통이 열려 있으면 그리로 옮기고(배낭 ↔ 창고·작업대·시체, `InventoryGridUI.FindCounterpart`), 배낭만 열려 있으면 **장비를 입고 음식을 먹는다**(이미 찬 것은 `Equipment`가 배낭으로 돌려준다). 둘을 다른 조작으로 가르지 않는 이유: 우클릭으로 하려는 일은 늘 **"이걸 저기로"** 하나이고 "저기"만 상황마다 다르다 — **음식의 "저기"는 입이다**(동전의 저기가 지갑, 장비의 저기가 몸인 것과 같은 자리). 들어간 만큼만 빠지므로 자리가 모자라면 나머지는 그대로 남는다. **창고의 검은 안 입힌다** — 어느 폰이 입는지 말할 수 없다(**창고의 밥도 같은 이유로 안 먹는다** — 폰이 먹으러 가는 것은 `EatNode` 몫이다)
  - **밥은 그 자리에서 즉시 먹는다**(`QuickEat`, 2026-08-20). 먹는 것은 원래 폰이 알아서 하지만(`EatNode`) 그건 *배가 고파졌을 때*의 일이라 **지금 채워 두고 싶을 때**의 길이 없었다(싸우러 나가기 전·원정 전·임계 바로 위에서 어정거릴 때). **누른 그 뭉치를 먹는다** — `Feeding.ConsumeFrom`은 같은 종류를 아무거나 빼므로 안 쓴다(`QuickEquip`이 인스턴스 경로로 가는 것과 같은 이유). **통이 열려 있으면 옮기는 쪽이 이긴다** — 옮기기는 무를 수 있지만 먹은 것은 못 무른다. **배가 꽉 찼을 때만 거절한다**(한 끼가 통째로 사라진다) — 그 아래로 넘치는 것은 손으로 시킨 사람의 몫이다(`Feeding.Better`는 *자동*이 낭비하지 않게 있는 규칙이다). **갇힌 사람은 제 손으로 못 먹는다** — 그게 간수를 두는 이유이고, 여기서 뚫리면 포로 소지품 창을 열어 공짜로 먹이는 길이 된다. **잠근 뭉치도 먹는다**(잠금은 자동을 막으려고 있다). 기절한 폰과 **원정 나간 폰**(GameObject가 꺼져 있어 허기가 안 돈다 — 채워 봐야 밥만 사라진다)은 못 먹는다
  - **답은 그 아이콘 자리에서 온다** — 먹으면 **줄어들며 사라지는 잔상**(`DraggableItem.FlashUsed` → `ItemUsePulse`), 못 먹으면 **흔들림**(`FlashRefused` — 못 놓은 물건을 흔드는 것과 같은 낱말이다). 즉시 처리라 아무 반응이 없으면 **뭉치 개수만 줄어서** 먹였는지 확신이 안 서고, 한 번 더 눌러 한 끼가 더 사라진다. **폰 머리 위 팝업은 안 띄운다** — 배낭에서 하는 조작인데 답이 창 밖에서 나면 내가 누른 결과로 안 보인다. 수치(`허기 +30`, 버린 양)는 콘솔에만 남긴다 — 얼마나 찼는지는 살펴보기 창의 허기 바가 실시간으로 말한다
  - **잔상은 격자 바깥(캔버스 아래)에 선다** — 개수가 줄면 `Inventory.OnChanged` → `InventoryGridUI.Refresh`가 **아이콘을 전부 파괴하고 다시 만들어서**, 그 아이콘을 직접 애니메이션하면 코루틴째 죽는다. **거절은 반대로 그 아이콘을 직접 흔든다**(아무것도 안 바뀌었으니 살아 있다)
  - **배가 찼으면 못 먹는다 — 다만 여백을 둔다**(`FullMargin` 1). 딱 100일 때만 막으면 **그 순간이 한 프레임뿐이라**(허기는 매 프레임 준다) 화면에 `100/100`이라 적혀 있는데도 계속 먹혔다
  - **뭉치 쪼개기 — 집을 때 갈린다**: `Shift` = 절반, `Ctrl` = 하나, 그냥 = 전부. 쪼개는 시점이 **집는 순간**이라 그 뒤로는 평범한 손에 든 것이다(놓을 수 있는 곳이 전부 그대로 통한다). **집어 든 쪽이 새 뭉치다** — 남는 쪽이 원래 자리를 지켜야 한다. 통이 꽉 차 놓을 칸이 없으면 **격자에 안 놓고 손에 들고**(`_detached`), 놓기에 실패하면 출처로 되돌린다(안 되돌리면 조용히 샌다). 알리는 것은 아이콘을 캔버스로 옮긴 **뒤**에 — 먼저 알리면 격자가 다시 그려지며 **손에 든 아이콘이 파괴된다**(`InventoryGridUI`가 `CarriedInstance`를 건너뛴다)
- `EquipSlotUI` — 장비 칸 6개. **장비칸을 컨테이너처럼 다룬다**: **좌클릭=집는다**(벗기와 집기가 한 동작 — `TakeOff`는 배낭을 안 거치므로 벗긴 그것이 곧 손에 든 것이다), **손에 들고 좌클릭=찬다**(원래 차던 것은 손에 들린다 — 격자에서 밀려난 것이 손에 들리는 것과 **같은 규칙**), **우클릭=벗어서 배낭으로**. 받는 곳은 어디서든 된다 — 내 배낭 · 상자 · 작업대 · **적 시체**, 그리고 **다른 장비칸**(내 것이든 시체 것이든).
  - **제 드래그를 따로 굴리지 않는다**(2026-08-19). 고스트 만들기·회전·미리보기·격자로 떨구기가 200줄쯤 이 파일에 두 벌로 있었는데, 손에 드는 상태가 생기면서 **전부 `DraggableItem` 하나로** 모였다. 여기 남은 것은 **이 칸이 무엇을 받고 무엇을 내놓는가**뿐이다(`Accepts`/`Wear`/`TakeOff`/`TryEquipCarried`). 커서 아래 칸은 정적 목록에서 `RectangleContainsScreenPoint`로 찾는다(`IDropHandler`가 없어져 유니티가 안 알려 준다).
  - **손에 뭉치가 남아 있으면 벗은 것은 배낭으로 간다** — 둘을 같이 들 수는 없다(철검 셋을 든 채 칸을 누르면 하나만 차고 둘은 손에 남는다).
  - **배낭을 안 거친다**(`Equipment.Wear*` — 인스턴스를 그대로 찬다). 원래 `Equip*`은 배낭에서 꺼내 차는 설계(`FindInInventory`+`RemoveOne`)라 밖에서 끌어온 것을 못 찾고 **조용히 실패했고**, 배낭 경유로 고쳤더니 이번엔 **배낭이 꽉 차면 빈 칸에도 못 넣었다**("칸은 비었는데 왜 안 들어가지"). 지금은 **벗겨지는 쪽만** 배낭으로 가고(자리 없으면 발밑), 들어오는 쪽은 자리를 안 본다.
  - **장착 지점을 셋으로 모았다** — `Equip*`(배낭 경로)도 전부 `Wear*`로 흐른다. 여럿이면 하나가 반드시 `SyncBlackboard`나 `OnEquipChanged`를 빠뜨린다.
  - 규칙: ① **맞는 칸인지 먼저 보고**(`Accepts`) 뺀다 — 못 찰 것을 옮겨 놓으면 시킨 적 없는 이동이 된다. ② **한 개만** 가져온다(상자에 철검이 셋이어도 차는 건 하나 — 뭉치째면 "착용"이 아니라 "가져오기"다). ③ 교환은 **양쪽 다 빼놓고 나서 채운다**(`TakeOff`는 배낭에 안 돌려준다) — 한쪽씩 하면 중간에 `ReturnToInventory`가 끼어들어 물건이 배낭·바닥으로 샌다. ④ **서로 받을 수 있을 때만** 바꾼다(한쪽만 되면 교환이 아니라 강탈이다).
  - 옮기는 것은 `ItemData`가 아니라 **`ItemInstance`** — 데이터만 넘기면 희귀 철검이 맞바꾸는 것만으로 일반이 된다.
  - **장비칸도 미리보기가 있다**(`EquipSlotUI.Hint` — 받아 주면 격자와 **같은 흰색**, 못 받으면 붉게). 격자만 놓일 칸을 그리고 장비칸은 아무 말이 없어서, 손에 든 것을 칸 위에 올려도 *"여기 놓으면 장착되는가"*를 알 수 없었다 — **차 있는 칸에서는 아예 "장착이 안 된다"로 읽혔다**(되는데도). **칸 배경(`bg`)을 물들이지 않는다** — 아이콘·프레임이 그 위를 덮어 **색은 칠해지는데 화면에는 안 보인다.** **맨 위에 사각형을 얹는다**(`SetAsLastSibling`) — 격자 미리보기와 같은 방식이라 가려질 수가 없고.
  - **바뀌면 칸이 한 번 반짝인다**(`EquipSlotUI.Flash`, 0.35초). **같은 물건을 맞바꾸면 티가 안 난다** — 칸의 그림도 손에 들린 것도 똑같아서 아무 일도 안 일어난 것처럼 보인다(등급만 다를 때가 특히). *거절은 흔들어서, 바뀐 것은 반짝여서* 말한다 — 알림을 띄우기엔 너무 잦은 일이다. 손에 벗겨진 것이 들려 있어 `Hint`가 계속 도는 김에 그려지므로, 반짝임만을 위한 `Update`를 칸마다 두지 않아도 된다.
  - **장비칸 위에서 거절당하면 거기서 끝이다** — 아래로 흘려보내면 배낭 격자가 장비 열을 덮고 있어 **못 찬 물건이 배낭에 툭 떨어진다**(보기엔 "그 칸에 안 놓인다"인데 실제로는 엉뚱한 데로 간 것이다). 거절 사유는 콘솔에 남긴다(`안 맞습니다` / `못 찼습니다`) — 거절하는 길이 셋인데 아무 말이 없으면 화면에서는 전부 "안 된다" 하나로 보인다.
  - **손에 든 그림·Q/E 회전·미리보기·놓일 칸이 격자와 같다** — 장비칸에서 집은 것도 `DraggableItem`이 드는 순간 격자에서 집은 것과 **구별이 없다**(`CarryDetached`). 2×4 갑옷을 들면 그만큼 큰 사각형이 커서를 따라오고, 놓을 자리는 `PlacementCell`이 답한다.
  - **격자 → 차고 있는 칸 = 맞바꾸기.** 벗은 것은 **온 곳으로 돌아간다**(상자에서 끌었으면 상자로). `Equipment.ReturnToInventory`에 맡기면 **폰의 배낭으로** 가서, 상자 갑옷을 입을 때마다 벗은 것이 배낭에 쌓이고 그걸 다시 상자로 옮겨야 한다 — **한 동작으로 보이는 일이 두 동작**이 된다. 못 받으면 배낭 → 발밑 순(증발 방지 순서)
- `ItemInfoUI` — 아이템 hover 시 공용 툴팁. **띄운 놈이 사라지면 스스로 닫는다**(`Show(..., owner: this)` + `LateUpdate` 감시) — `OnPointerExit`는 **오브젝트가 파괴되면 오지 않아서**, 커서를 얹은 채 격자 아이콘이나 상점 행이 없어지면(동전 더블클릭으로 잔고에 넣기·구매·판매·목록 갱신) 툴팁이 영영 남았다. **띄우는 쪽마다 `OnDestroy`를 다는 대신 여기서 지켜본다** — 부르는 곳이 넷이고 앞으로 늘 텐데 하나가 빠뜨리면 그 경로에서만 남아 원인을 찾기 어렵다. `owner`를 안 넘긴 곳은 스스로 `Hide()`한다(안 넘겼다고 곧바로 닫으면 그쪽이 통째로 못 뜬다). "안 넘김"과 "죽음"은 **`ReferenceEquals`로 가른다** — 유니티의 `== null`은 파괴된 것에도 참이라 둘이 같아 보인다. **이름줄은 이름만**이고 아랫줄이 `등급 · 종류`다(`희귀 · 양손 검`) — 이름 앞에 등급을 또 붙이면 같은 말이 두 번이고 긴 이름이 잘린다. 종류 이름은 **`ItemData.TypeName`이 답한다**(클래스가 오버라이드) — 밖에서 `is WeaponData`로 갈라 쓰면 종류가 늘 때마다 분기를 전부 찾아 고쳐야 하고 하나 빠뜨리면 조용히 "잡화"가 된다

**`MerchantUI`는 모드 무관이다** — 거래는 거점 상인에게도 하고 월드맵 마을에서도 한다. `GameModeManager`가 `MerchantUI`·`InventoryUI`·`ItemInfoUI`의 캔버스 직속 부모를 필드 UI 스태시에서 뺀다(씬 배열이 아니라 컴포넌트에서 부모를 타고 올라가 찾는다). 스태시에서 빼는 것뿐이라 저절로 열리진 않는다. 진입점 둘 — 필드는 `Merchant.OnSelected`, 월드는 `MerchantUI.OpenFor(shop, account, traders, title)`. 모드가 바뀌면 닫는다. 원정대 거래면 **누구 배낭을 볼지는 배낭 창이 갖는다** — `InventoryUI.SetPawnCycle(members)` → 적재 바(`CarryBar`) 오른쪽 끝의 [이전] 이름 (2/4) [다음]. 무게·짐내림·잠금이 이미 그 폰의 것이므로 폰 고르기도 같은 줄에 있어야 한다. 원정 나간 폰은 GameObject가 꺼져 있어 `SelectionManager`로는 배낭을 열 길이 없다(`BindTo`가 그 우회로).

**씬 구성**: `ItemInfoUI` + `MerchantUI`는 씬에 있고, 항목 행은 `MerchantStockEntry.prefab` / `SellItemEntry.prefab`을 복제해 채운다. 모양 수정은 인스펙터에서(생성기는 역할을 마쳐 제거됨 — `docs/editor_creators.md` "생성기의 수명").

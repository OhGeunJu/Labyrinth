# Combat System

## Damage Type System (`Combat/`)

**축은 하나다**(2026-08-23 — `DamageCategory` × `DamageElement` 2D 매트릭스를 접었다).

```
DamageType:
  물리  Slash / Pierce / Blunt          ← 갑옷이 막는다
  원소  Fire / Water / Earth / Lightning / Arcane / Dark / Holy   ← 저항이 막는다
```

`DamageTypeExt.IsPhysical()` 하나가 갈래를 답한다. `DamageInfo { Amount, Type, EffectChance,
IgnoreArmor, Source }`.

**물리:**
- `Slash` — 출혈 계수 0.25(가장 높다)
- `Pierce` — 갑옷 두께를 지나간다
- `Blunt` — 피해 ×1.3, 출혈 계수 0.05(부위로 눕힌다)

**원소 — 저마다 하나씩만 한다** (`EffectChance` 확률로 발동):

| 원소 | 피해 | 효과 |
|---|---|---|
| `Fire` | — | `Burning` 5초 5dps. **`Wet`을 말린다** |
| `Water` | — | `Wet` 8초(이동 −10%) |
| `Earth` | — | `TryKnockOut(bonus 0.35)` — 켄시식 KO 굴림에 직접 얹힌다 |
| `Lightning` | ×1.2, **젖었으면 추가 ×1.5** | `Slowed` 8초(경직) |
| `Arcane` | — | **갑옷·저항을 지나간다.** 상태이상 없음 |
| `Dark` | — | `HealReduction` 10초 + `CorruptionGauge` +amount×0.3 |
| `Holy` | **언데드에게 ×2** | 휘두른 쪽 회복 30/부위 10 + 디버프 제거 |

- **독은 원소가 아니다** — 효과다(불이 화상을 주듯). `StatusEffectSystem`이 든다.
- **`Holy` ×2는 저항표가 아니라 `UnitBrain.IsUndead`가 답한다.** 표에만 적으면 **일으켜진
  몸**은 사람 종족이라 표에 없어서 성물이 안 듣는다 — 시체가 일어나는 게임에서 그건 신성을
  넣은 뜻을 통째로 지운다.
- **`Water` 하나로는 약하다 — 전기 증폭이 그것을 산다.** 원소끼리 얽히는 유일한 자리라,
  없으면 물은 색만 다른 감속기다.

### 저항 (`DamageResistance`)

**저항이 없으면 원소는 장식이다** — 무기를 바꿀 이유가 없어진다.

두 곳이 들고 **더해진다**: `ArmorData.Resistances`(입은 것) · `UnitData.Resistances`(타고난 것).
`Multiplier()`가 `1 - Σ`를 **0.1~3.0으로 자른다**(음수 = 취약). 완전 면역을 안 만드는 이유:
화면에서 *"안 맞는다"*로 보여 무엇이 일어나는지 알 수가 없다.

**갑옷의 `DamageReduction`은 물리에만 걸린다** — 원소는 두께가 아니라 재질의 문제다.

저작된 종족 저항:

| 종족 | 저항 |
|---|---|
| 해골 | 베기 0.4 · **타격 −0.35** · 암흑 0.75 · 불 0.2 (+ 신성 ×2는 `IsUndead`) |
| 곰 | 베기 0.2 · 불 −0.3 |
| 늑대 | 전기 −0.25 |
| 고블린 | 암흑 0.25 · 신성 −0.2 |

### 무기

`WeaponData.DamageType` 하나. **마법 무기는 `WeaponType.Staff` 하나**이고 무엇을 쏘느냐는
`DamageType`이 정한다 — 종류로도 가르면 원소를 더할 때마다 `WeaponType`이 같이 는다.
(옛 추론 사다리 셋 `IsMagicWeapon`·`CategoryFromType`·`ElementFromType`은 없어졌다.)

**어느 스탯이 자라나는 `UnitStats.StatFor(WeaponData)` 하나가 답한다** — 지팡이는 `Type`만
봐서는 못 가른다(전부 `Staff`). JSON은 `"damageType"`, 옛 세 키(`damageCategory`·
`physicalType`·`damageElement`)는 `DataManager.MigrateLegacyDamage`가 읽어 옮기고 경고한다.

## Status Effect System (`StatusEffectSystem.cs`)

`UnitBrain.Awake`에서 자동 추가.

| 효과 | 영향 |
|---|---|
| `Burning` | `BodyPartSystem.TakeDamage` DoT 매 프레임 |
| `HealReduction` | `HealMult < 1` |
| `Slowed` | `AttackIntervalMult > 1`, `MoveSpeedMult < 1` (전기의 경직) |
| `Hasted` | `MoveSpeedMult > 1` (SubCore 범위 효과) |
| `Weakened` | `AttackChanceMod < 1`, `DefenseChanceMod < 1` |
| `CorruptionGauge` | 회복 불가 2차 피통 (암흑 누적) |
| **`Wet`** | `MoveSpeedMult` −10%. **`BodyPartSystem`이 `IsWet`을 보고 전기 피해 ×1.5** — 이게 물의 본체다 |

- `IsWet` / `DryOff()` — 불이 물을 말린다(안 그러면 불·전기가 둘 다 잘 드는 공짜 조합).
- `ClearDebuffs()`가 `Wet`도 걷어낸다.

- `ApplyEffect(type, duration, strength)` — 동일 타입이면 duration/strength 갱신
- `AddCorruption(amount)` — 부패 게이지 누적

## Kenshi-style XP System (`CombatXp.cs`)

전투/노동 스킬 성장에 켄시 RPG 방식의 XP 보정 적용. 모든 성장 호출은 `UnitStats.GrowStat()`을 통과 (IsLocked 미니언 차단).

### 3가지 보정 곱

```
최종 XP = baseAmount × ChallengeMult × Sol × OutnumberedMult × eventMult
```

**`ChallengeMult(mySkill, oppSkill)`** — 상대 스킬 차이 배율:
- 상대보다 29.25 위 → 0.1x (최소)
- 동급 → 1.0x
- 상대보다 65 아래 → 6.0x (최대)
- 선형 보간

**`Sol(mySkill)`** — 후반 둔화: `(1 - skill/131)²`
- 레벨 10 (F+) ≈ 0.85x
- 레벨 50 (C+) ≈ 0.38x
- 레벨 100 (S+) ≈ 0.05x
- 레벨 120 (SSS-) ≈ 0.006x

**`OutnumberedMult(enemyCount)`** — 수적 열세 보너스: `1 + (n-1) × 0.1`, 캡 1.666x at 1v8+. `CountNearbyEnemies(self, radius=6f)`로 자동 카운트.

### CombatHandler 이벤트별 XP 배율

**막았으면 방어가, 피했으면 회피가, 맞았으면 강인함이 자란다**(2026-08-26). 켄시의 배치다 —
**못 막고 못 피한 것이라 그 솜씨가 늘 이유가 없고**, 배우는 것은 *아픔을 견디는 법*이다.

| 상황 | 방어자 | 공격자 |
|---|---|---|
| Block 성공 | 방어(맨손=무술) **3.0x** + **Shield 3.0x** | 무기 0.5x, MeleeAttack 0.25x(원거리는 인지력 0.25x) |
| Dodge 성공 | Evasion **1.5x** | 0 (히트박스 미접촉) |
| 피격 (적중) | **Toughness 1.0x** | 무기 1.0x, MeleeAttack 0.5x(원거리는 인지력 0.5x) |

근접·원거리가 **같은 표**다(방어 스탯이 하나이므로).

**사건당 기대 성장**(파리티: 막기 13.6% · 회피 22.7% · 피격 63.7%) — 넷이 나란하다:

```
무기 0.705 · 강인함 0.637 · 방어 0.408 · 근접공격 0.353 · 회피 0.340
```

**8배는 걷어냈다.** 근거가 어디에도 없었고(2026-06-04에 그냥 들어왔다) 셋이 어긋나 있었다:
같은 줄에서 **방어 8배 ↔ 회피 2배** · `ChallengeMult`(최대 6배)와 곱해 **48배** ·
**막는 데 성공할수록 손해**. 무엇보다 **방어가 다른 전투 스탯보다 7~15배 빨리 자랐다**(5.255).
떼면 방어가 막기에서만 자라 2.6%로 죽으므로 **막기 배수를 3.0으로 같이 올렸다.**

**`Shield`는 방패를 들고 있을 때만 얹는다**(`GrowShieldXp` → `HasShield`). 이제 **막았을 때만**
자라므로 방패가 방패 노릇을 한다 — 전에는 맞을 때마다 8배로 올랐다.

**강인함은 이 길이 생기기 전까지 도발을 쓸 때만 자랐다**(`AbilityUser`) — 도발 능력이 붙은
장비를 안 찬 폰은 기절 저항·피해 감소·지도 전력을 정하는 스탯이 **평생 그대로**였다.

### 속성 넷은 저마다 자라는 길이 하나씩이다 (2026-08-26)

| 속성 | 자라는 자리 | 하는 일 |
|---|---|---|
| 근력 | 짐을 지고 걷기(`PawnMover.GrowStrengthFromLoad`) | 적재 한도 · 피해 |
| 강인함 | **맞기**(`CombatHandler`, 1.0x) | 기절 저항 · 피해 감소 · 도발 |
| 인지력 | **원거리 명중**(막힘 0.25x / 명중 0.5x) | 원거리 명중 · 사거리 |
| 손재주 | **근접 공격**(막힘 0.25x / 명중 0.5x) | 근접 공격 간격 · 베기 피해 |

**넷 다 길이 있어야 한다** — 강인함은 도발을 쓸 때만, 손재주는 **아무 데서도** 안 자라서
태어난 값 그대로 평생 갔다(둘 다 08-26에 닫았다).

### 노동/제작/연구 적용

- **`BTLeafNodes` WorkNode** — Mining/Cutting 성장. `node.Data.RequiredSkill`을 도전 대상으로 사용. `0.05 × deltaTime × ChallengeMult × Sol`
- **`CraftJob`** — `_recipe.SkillGrowthAmount × ChallengeMult(skill, requiredSkillLevel) × Sol`
- **`ResearchJob`** — `SkillGrowthAmount × Sol` (도전 대상 없음)
- **`PawnMover` Athletics** — `growthRate × deltaTime × Sol` (도전 대상 없음)
- **`CombatHandler` PrecisionShooting** — `growthRate × Sol` (도전 대상 없음)

### ResourceNodeData

`RequiredSkill: float` — 자원별 권장 스킬 레벨 (XP 도전 비율 계산용). 0이면 누구나 같은 속도로 성장.

## Combat System (`CombatHandler.cs`)

`Equipment.MainHand`로 무기 타입 결정. `CombatHandler.Update()`에서 `weapon.IsRanged`로 분기.

**안 맞는 것은 한 물음이다 — `Measure`가 근접·원거리에 같이 답한다**(2026-08-24):
1. Weakened 디버프: attackSkill × AttackChanceMod
2. `blockRaw` = OpposedChance(Defense + 방패보너스, attackSkill) × `blockWeight`(0.75)
   — 맨손이면 `MartialArts`, 방패 보너스는 근접 `BlockBonus` ↔ 원거리 `RangedBlockBonus`
3. `dodgeRaw` = OpposedChance(Evasion, attackSkill) × `dodgeWeight`(1.25)
4. **몫**은 `blockRaw : dodgeRaw`로 먼저 고정, **총량**은 둘을 겹쳐 재 × DefenseChanceMod
   → `maxAvoidChance`(0.6)로 자른다 — **천장은 *방어자의 솜씨*에만 걸린다**
5. 총량을 몫대로 갈라 **막기 → (실패하면) 회피** 두 굴림
6. 피격 → `BodyPartSystem.TakeDamage(DamageInfo)`

**공격자 쪽 스탯**은 근접 `MeleeAttack`(맨손 `MartialArts`) ↔ 원거리 **`Cognition`**(2026-08-26).
움직이는 표적이면 명중 솜씨가 `Lerp(0.6, 1, 인지력/130)`만큼만 남는다 — **그 깎임을 지우는
것도 인지력**이라 키우면 이긴다.

**원거리 스탯 셋 — 하는 일이 하나씩이다**(2026-08-26):

| 스탯 | 하는 일 | 눈금 |
|---|---|---|
| `Cognition` | 명중 · 움직이는 표적 · **사거리** | 130 → 사거리 1.5배(석궁 14 → 21m) |
| `PrecisionShooting` | **겨눈 것을 맞히나**(그것 하나) | 빗나갈 확률 `(1 − 정밀/130) × 0.4` |
| 무기 숙련(`Bow`·`Crossbow`·`Javelin`·지팡이 7) | **재장전** | 130 → 1.5배 빠름(3.4 → 2.27s) |

- 사거리는 `UnitBlackboard.AttackRange`(프로퍼티) = `BaseAttackRange × CombatHandler.RangeMult`.
  배수가 붙을지는 `RangedWeapon`이 가른다.
- 원거리 재장전에는 손재주·근력이 **안 걸린다**(근접 몫). 원거리 피해에 무기 숙련도 **안 얹힌다**
  (재장전이 곧 DPS라 두 번 값을 하면 안 된다). 근접은 둘 다 예전 그대로.

**빗맞음** — `TryFireRanged`가 막기·회피보다 **먼저** 굴린다(겨냥이 흔들린 것이라 겨눈 쪽은
관여 안 함): `FactionScan.NearestPawnInCone`이 표적 방향 **반각 20° · 표적까지**의 부채꼴에서
가장 가까운 사람을 찾는다. **세력을 안 가린다** — 동료면 손해고 옆에 선 다른 적이면 그냥 다른
놈이 맞는다. **아무도 없으면 굴림 자체가 없다**(허허벌판의 한 놈은 늘 겨눈 대로 맞는다).
**겨눈 표적은 뺀다**(`exclude`) · 쓰러진 몸·시체는 `IsAttackable`이 뺀다.

**데미지 공식:**
```
damage = AttackDamage
       × (1 + weaponSkill / 100)
       × [1 + Dexterity/100 × 0.5]   // IsBladed 무기만
       × [1 + Strength/100 × 0.5]    // 비무장만
       × statusCorrection
       × weightCorrection
```

**공격 인터벌 공식:**
```
interval = weapon.BaseAttackInterval
         / (1 + Dexterity/100)
         / [1 + Strength/100 × 0.5]  // IsLargeWeapon만
         / statusCorrection
         / weightCorrection
         × AttackIntervalMult        // StatusEffectSystem (Slowed 등)
```

**무게 보정:** `maxCarryWeight = Strength × 5`. 초과 시: `weightCorrection = maxWeight / currentWeight`

**상태 보정** (사지 장애):
- RightArm × 0.5 + LeftArm × 0.3 + RightLeg × 0.1 + LeftLeg × 0.1
- 양팔 OR 양다리 모두 장애 → 0

## Body-Part System (`BodyPartSystem.cs`)

7개 부위: Head, Chest, Abdomen, LeftArm, RightArm, LeftLeg, RightLeg

**타격 부위 추첨** (`GetRandomBodyPart`): 균등이 아니라 `BodyPart.HitWeight` 가중치 — 가슴 30 / 복부 20 / 머리 10 / 사지 각 10 (합 100). 몸통 50%, 머리 10%(작은 표적). 부위별 튜닝은 `InitBodyParts`.

| 상태 | 임계값 | Head/Chest/Abdomen | Arm | Leg |
|---|---|---|---|---|
| Disabled | ≤ 0 | TryKnockOut | AttackAbility 갱신 | SetLimping/Crawling |
| Destroyed | ≤ −100 | Die() | TryKnockOut | TryKnockOut |

- `TryKnockOut`: `resistChance = Toughness / 100`. 실패 → `IsKnockedOut = true`
- `TryKnockOut(bonus)` — `bonus`는 넘어뜨리는 쪽의 보정(땅 원소가 0.35). **저항에서 곧장 뺀다** — 강인함을 깎는 식으로 넣으면 같은 값이 사망 문턱 같은 다른 판정에도 새어 나간다.
- `TakeDamage(DamageInfo)` 처리 순서:
  1. 타입 배율 (Blunt ×1.3, Lightning ×1.2) + **젖음 ×1.5**(전기) + **언데드 ×2**(신성)
  2. 보호막 흡수
  3. **물리면** 갑옷 `DamageReduction × qualityMult`(Pierce 관통) / **원소면** 저항 배율
     — `Arcane`은 **둘 다 지나간다**
  4. Toughness 저항 `/ (1 + Toughness/100)`
  5. 출혈 (Slash 0.25 / Blunt 0.05 / 그 밖 0.125)
  6. 상태이상 발동 (EffectChance 확률)

**부위 → 갑옷 슬롯 매핑:** Head→Head, Chest/Abdomen→Chest, Arms→Hands, Legs→Legs

## 방패 스탯 (`StatName.Shield`)

**무기는 종류마다 스탯이 있는데 방패만 없었다**(2026-08-23까지) — `WeaponToStat`에서
`WeaponType.Shield`만 `_ => MartialArts` 폴백에 떨어졌고, 막기 계산은 평탄 `BlockBonus`만
더했다. **그래서 방패는 자라지 않았다**: 천 번을 막아도 나아지지 않고 좋은 방패를 사는 것이
유일한 개선이었다.

**무기와 대칭이다** — 공통 스탯이 굴림, 종류 스탯이 크기:

| | 공통 | 종류 |
|---|---|---|
| 공격 | `MeleeAttack` (맞히나) | `OneHandSword` 등 (얼마나 아픈가) |
| 원거리 | `PrecisionShooting` | `Bow`·`Crossbow`·`Javelin` / **지팡이는 원소 스탯** |
| 방어 | `MeleeDefense` (막나) | **`Shield`** (방패가 얼마나 일하나) |

```
effective = MeleeDefense + BlockBonus × (1 + Shield / 100)
```

- **`MeleeDefense`를 대체하지 않는다** — 그건 무기로 흘리고 몸으로 피하는 것이라 방패가
  없어도 돈다.
- **방패가 없으면 저절로 0이다**(`BlockBonus` 0 × 무엇 = 0) — *"방패를 든 폰만 자란다"*가
  규칙을 따로 만들지 않아도 나온다. 스탯 창에도 **들고 있을 때만** 뜬다.
- **근접·원거리를 안 가른다** — `RangedBlockBonus`도 같은 스탯을 탄다. 가르면 방패 하나에
  스탯이 둘이 되고, 그건 방패를 두 물건으로 만드는 것이다.

## 마법 스탯 — 원소 일곱 (15 → 7)

전에는 계열 셋(`ElementalMagic`·`DarkMagic`·`HolyMagic`) × 원소 넷 = **열다섯**이었다.
**계열 셋은 전투에서 한 번도 안 읽혔고**(`GetMagicCategorySkill`을 부르는 곳이 없었다)
조합 열둘 중 **여덟은 무기가 아예 없었다.**

지금은 `FireMagic` · `WaterMagic` · `EarthMagic` · `LightningMagic` · `ArcaneMagic` ·
`DarkMagic` · `HolyMagic`. **`UnitStats.MagicStatFor(DamageType)`**가 짝을 짓는다.

**`StatName` 정수 자리를 옮겼으므로 에셋도 같이 옮겼다**(45개 파일) — 실제로 저작에 쓰이던
마법 스탯은 옛 `DarkMagic`(19)뿐이었고(교단 성장 배경 다섯) 그건 새 자리(23)에 그대로 산다.
**스탯은 53 → 46개**(마법 −8, `Shield` +1).

# CLAUDE.md에서 내려온 상세 (2026-08-27)

아래는 `CLAUDE.md`가 150,000자 한도를 넘겨 내려온 절들이다. 요약과 단일 출처 이름은
`CLAUDE.md`의 "전투 — 피해 · 능동 능력 · 몸 · 치료 · 기절과 시체"에 남아 있다.

## Damage Quick Ref — **축은 하나다**

```
DamageType:  물리 Slash / Pierce / Blunt        ← 갑옷이 막는다
             원소 Fire / Water / Earth / Lightning / Arcane / Dark / Holy  ← 저항이 막는다
```

2026-08-23에 `DamageCategory` × `DamageElement` 2D를 접었다 — **물음 하나에 답이 둘**이었고,
그 결과 열두 칸 중 `Holy` 넉 줄은 효과가 아예 없고 `Dark`·`Holy` 무기는 0개였다.

- **원소마다 하는 일이 하나씩**(불=화상 · 물=젖음 → **전기 ×1.5** · 땅=기절 굴림 +0.35 ·
  전기=경직 · 비전=**갑옷·저항 무시** · 암흑=회복 차단+부패 · 신성=**언데드 ×2**).
  **독은 원소가 아니라 효과다** — `StatusEffectSystem`이 든다.
- **신성 ×2는 저항표가 아니라 `UnitBrain.IsUndead`가 답한다** — 표에 적으면 **일으켜진 몸**은
  사람 종족이라 표에 없어서 성물이 안 듣는다.
- **저항이 없으면 원소는 장식이다** — `ArmorData.Resistances` + `UnitData.Resistances`가
  더해진다(`DamageResistance.Multiplier`, 0.1~3.0). **갑옷의 `DamageReduction`은 물리에만.**
- **마법 무기는 `WeaponType.Staff` 하나** — 무엇을 쏘느냐는 `DamageType`이 든다. 어느 스탯이
  자라는지는 **`UnitStats.StatFor(WeaponData)` 하나**가 답한다(`Type`만 보면 불과 암흑이 같아진다).
- **마법 스탯 15 → 7**(계열 셋은 전투에서 한 번도 안 읽혔다). **`Shield` 신설** — 방패만
  스탯이 없어 자라지 않았다. `Defense`(막나) × `Shield`(방패가 얼마나 일하나)로 무기와
  대칭이고, 방패를 안 들면 `BlockBonus` 0이 곱해져 저절로 아무것도 안 한다. **스탯 53 → 45개.** **방어도 하나로 접혔다**(2026-08-23) — `MeleeDefense`·`RangedDefense`가 `Defense` 하나다. *"막는 솜씨"*라는 물음은 하나뿐이고 **날아오는 것을 막는 것도 막는 것**이다. 둘로 두던 진짜 이유(방패가 근접·원거리를 다르게 막는다)는 **방패가 든다**(`BlockBonus` ↔ `RangedBlockBonus`) — 스탯을 갈라 두면 같은 것을 두 번 표현하는 셈이고, 실제로 `RangedDefense`는 **저작 에셋에서 한 번도 안 쓰였다**. 그리고 **원거리에도 회피를 붙였다** — 전에는 근접만 *막기 → 회피* 둘을 굴리고 원거리는 막기 한 번뿐이라 **같은 폰이 칼보다 화살에 훨씬 잘 맞았다**
- **안 맞는 것은 한 물음이라 같이 잰다 — `CombatHandler.Measure`**(2026-08-24). 막기와 회피를 **따로 굴리면 총량에 천장을 씌울 자리가 없다**: 둘 다 멀쩡해 보이는데 합이 96%가 된다. 실제로 그랬다 — 몫(`blockWeight` 0.75 / `dodgeWeight` 1.25)을 **파리티(공격=방어)에서만 재고 맞춰서**, 방어 100 대 공격 20이면 **27:1**로 안 맞고 방어 130 대 공격 10에서는 `dodgeWeight`가 확률을 1 너머로 밀어 `Random.value < 1.25`가 **항상 참** — 회피 100%로 굳었다. **키운 폰은 약한 적에게 영영 안 맞았다.** **총량을 먼저 정하고 몫으로 나눈다**: 몫(`blockRaw : dodgeRaw` = 37.5 : 62.5)을 먼저 잡고, 총량은 둘을 겹쳐 재 `maxAvoidChance`(0.6)로 자른 뒤 그 몫대로 갈라 **막기 → (실패하면) 회피** 두 굴림으로 되돌린다. **그래야 비율이 격차와 무관하게 일정하다** — 차례로 굴리면 막기가 커질수록 회피에게 남는 자리가 줄어 `0.75p = (1−0.75p)×1.25p` → **p = 0.533**(방어자가 공격자보다 **2.75배** 높을 때)에서 **기여가 뒤집힌다.** 당시 원거리는 거리·움직임이 **공격자 쪽만** 깎아 그 배수를 쉽게 넘었고, 그래서 등급이 같아도 멀리서 쏘면 **회피보다 방어가 더 자주 떴다**(그 감점은 08-26에 없어졌지만 **몫을 고정하는 이유는 남는다** — 격차는 다른 데서도 벌어진다)**파리티는 안 건드린다**(36% 그대로)
- **원거리도 굴림은 하나다 — `TryFireRanged` → `Measure`**(2026-08-24). 전에는 **셋**이었다: ① 조준(`인지력/100 × 거리 × 움직임`) ② 명중(`0.6 + 정밀/100 × 0.4`) ③ 방어자의 막기·회피. 곱하면 평범한 상황에서 **16%, 여섯 발에 한 대**였고 방어자가 자란 폰이면 1% 아래였다 — 근접은 대립 하나뿐인데 원거리만 셋이라 **같은 폰이 화살로는 아무것도 못 했다.** **게다가 ①이 `인지력/100`이라 인지력 0이면 정밀사격이 얼마든 명중 0%였다**(쏘는 솜씨를 정하는 스탯이 명중을 못 정하고 있었다). **원거리 스탯 셋은 하는 일이 하나씩이다**(2026-08-26, 사용자 결정). 그전에는 `정밀사격` 하나가 명중을 다 정하고, 무기 숙련은 피해에 얹히고, **`인지력`은 전투에서 아무것도 안 했다.**

  | 스탯 | 하는 일 |
  |---|---|
  | **인지력** | **맞나** — 대립 굴림의 공격자 쪽 + **움직이는 표적**을 읽는다 + **사거리** |
  | **정밀사격** | **아군 오사 확률.** 그것 하나다 |
  | **무기 숙련**(활·쇠뇌·지팡이…) | **재장전.** 원거리 피해에서는 빠졌다 |

  **사거리를 인지력에 둔 이유**: 명중과 사거리는 *"얼마나 멀리 있는 것을 맞히나"*라는 한 물음의 두 면이다. **확률이 아니라 경계로** 표현하는 것이라 화면에 보인다 — 인지력이 낮은 폰은 **가까이 붙어야 쏜다**(`FightNode`가 사거리 밖에서는 안 쏘므로 저절로 걸어 들어간다). 그리고 사거리는 **폰의 성질**이라 무기를 바꿔도 따라온다: 무기 숙련에 몰아넣으면 그건 이미 재장전이 하는 말이다. **`UnitBlackboard.AttackRange`가 프로퍼티인 것이 요점이다**(`BaseAttackRange` × `CombatHandler.RangeMult`) — 묻는 곳이 여덟이라 한 곳에서 곱해야 하고, **장착할 때 한 번 구워 두면 키운 인지력이 영영 안 붙는다**(다시 차야 반영된다). 배수가 붙을지는 `RangedWeapon`이 가른다 — 안 가르면 칼을 든 폰이 두 칸 밖에서 휘두른다. **재장전에서 손재주·근력은 근접 몫으로 물러났다**(한 손잡이를 두 스탯이 잡으면 무엇을 키워야 빨라지는지가 안 읽힌다). **원거리 피해에 무기 숙련을 안 얹는 것**은 **재장전이 곧 DPS**여서다 — 둘 다 주면 숙련 1점이 두 번 값을 해 그 축이 다른 모든 선택을 덮는다(근접은 그대로 피해에 얹힌다). 눈금: 인지력 130 → 사거리 1.5배(석궁 14→21m) · 무기 숙련 130 → 재장전 1.5배(3.4→2.27초) · 명중은 방어자 50/50 상대로 인지력 50이면 **63.7%(선 표적)/51.9%(뛰는 표적)**, 130이면 **89%/89%**. **상수다** — `[SerializeField]`면 프리팹 스물여섯이 저마다 값을 들어 코드 기본값이 힘을 잃는다.
- **빗맞음 — `정밀사격`이 답하는 것은 이것 하나다**(2026-08-26). **겨눈 것을 맞히나**를 정하고, 빗나가면 화살이 사라지지 않고 **부채꼴 안의 다른 누군가**가 맞는다. **세력을 안 가린다**(사용자 결정) — 동료면 손해고 옆에 선 다른 적이면 그냥 다른 놈이 맞는다. 한때 비적대만 훑었는데 그러면 *"적들만 있는 난전에 대고 쏘면 정밀사격이 아무 일도 안 한다"*가 되어 **겨눈 놈을 마무리하려는 바로 그 순간에** 그 스탯이 사라졌다 — 지금은 **표적을 고르는 스탯**이다. **부채꼴이 비어 있으면 굴림 자체가 없다**: 매 발 굴리면 정밀사격이 결국 명중도 깎아(그 발을 버리므로) **인지력에 준 축을 나눠 갖는다.** 그래서 허허벌판의 한 놈은 늘 겨눈 대로 맞고, **난전에 대고 쏘는 것**이 가장 위험하다. **선이 아니라 부채꼴이다**(사용자 결정 — 가는 선으로 재면 동료가 그 위에 정확히 서야만 걸려 **규칙은 있는데 거의 안 난다**): 표적 방향으로 **반각 20°, 표적까지**. 사거리 끝까지 안 재는 것은 **눈으로 재는 것과 같아야** 하기 때문이다(적 너머에 선 동료는 *"내 앞"*으로 안 읽힌다). 덤으로 **멀리서 쏠수록 쐐기가 길고 넓어져** 앞에 끼는 동료가 는다. 확률은 `(1 − 정밀사격/130) × 0.4`(정밀 0 → 40% · 65 → 20% · 130 → 0%). 훑는 것은 **`FactionScan.NearestPawnInCone`** — 적대를 찾는 셋과 나란한 자리이고, 쓰러진 몸·시체는 `IsAttackable`이 뺀다. **겨눈 표적은 반드시 뺀다**(`exclude`) — 안 빼면 부채꼴의 축 위 정확히 그 거리에 있는 표적 자신이 **제 몫의 빗맞음 대상**이 된다. 화살대 색도 갈린다(`ShotTracer`의 `stray`) — 그 색이 말하는 것은 *"겨눈 데로 안 갔다"* 하나다. **한때 *표적이 회피하면 화살이 뒤로 지나가 동료에게 간다*는 길이 따로 있었다**(08-23~08-26) — 걷어냈다: 그건 **방어자의 솜씨가 우리 편을 다치게 하는 것**이라 플레이어가 손댈 자리가 없고, 규칙이 둘이면 *"정밀사격 = 오사 확률"*이 거짓이 된다
- **싸우는 동안 표적을 본다 — `PawnMover.FaceTowards`**(2026-08-24). 그전까지 **`LookRotation`이 코드 어디에도 없어** 폰이 태어난 방향을 영영 보고 섰고, **석궁을 옆으로 쏘고 칼을 등 뒤로 휘둘렀다.** **도는 것은 `PawnMover`가 든다** — 자세(잠·기절·업힘)를 그쪽이 이미 들고 있어 밖에서 `rotation`을 만지면 **누운 폰을 세우거나 업힌 폰을 어깨 위에서 돌린다.** 누운 폰은 안 돌고 **수평만** 돈다(위아래로 겨누면 발이 뜬다)
- **걸어가는 쪽도 본다 — `PawnMover.FaceDirection`**(2026-08-25). 08-24에 넣은 것은 *싸우는 동안*뿐이라 폰은 여전히 **옆걸음·뒷걸음으로 맵을 가로질렀다.** 겨누는 것과 같은 함수를 쓴다(다른 것은 표적의 자리냐 실제로 가는 방향이냐뿐이고, 자세 가드와 수평 제약은 한 벌이어야 한다). 도는 것은 조향 결과(`steer`, 회피가 섞인 값)지 목적지 방향이 아니다. **싸우는 중이면 표적이 이긴다** — `MonoBehaviour` 실행 순서가 정해져 있지 않아 둘 다 쓰게 두면 **어느 쪽이 이길지가 프레임마다 갈려 몸이 떤다.** 보통은 겹치지도 않는다(`FightNode`가 사거리 밖에서는 `ExitCombat`, 안에서는 `StopMovement`라 걷는 동안엔 전투가 꺼져 있다) — 막는 것은 그 사이에 낀 프레임뿐이다. **그래서 근접은 걸어가며 못 친다** — 조준 게이트를 근접에 안 건 것과는 다른 이야기다
- **화살대가 날아간다 — `ShotTracer`**(2026-08-24). 짧은 화살대(1.1m)가 경로를 따라 가고, **나는 시간은 거리에 비례한다**(42 m/s) — 고정 시간이면 코앞과 사거리 끝이 같은 속도라 **거리가 화면에서 사라진다.** **꼬리를 민다**(머리 기준이면 끝에서 화살이 표적을 지나쳐 나간다). **도착해서 피해를 주지는 않는다** — 판정은 쏘는 순간 이미 끝나 있고(`DealRangedDamage`), 묶으면 표적이 그새 움직이거나 죽었을 때 **화살이 허공을 지나가는데 피가 깎인다.** 오사는 색이 다르다. 머티리얼은 `OverlayMaterial` 한 벌(깊이 판정 없음), 오브젝트는 풀에서 꺼낸다. 수명은 `unscaledDeltaTime`으로 잰다 — 안 그러면 멈춘 동안 화면에 얼어붙는다. - **조준은 정지로 표현한다 — `aimTime`(0.55초)**(2026-08-24). 간격의 마지막 구간에 **움직이면 조준이 풀린다.** 머리 위 게이지가 아닌 이유: 난전에서 바가 열 개씩 뜨면 화면이 지저분하고, **움직임은 그 자체로 읽힌다.** 딸려 오는 것이 요점이다 — **밀고 들어가면 사수가 못 쏜다.** **되돌리는 것은 조준뿐이다**(`Min`으로 경계까지만) — 타이머를 0으로 밀면 사수를 슬쩍슬쩍 건드리는 것만으로 **영영 못 쏘게** 만들 수 있다. **근접은 안 건다**(칼은 걸어 들어가며 휘두른다)
- **`StatName` 정수 자리가 옮겨졌다** — 에셋 45개를 같이 옮겼다(쓰이던 것은 옛 `DarkMagic` 19
  하나뿐이었고 새 자리 23에 산다). **앞으로도 뒤에만 붙일 것.**

## 능동 능력 — 장비가 준다 (`AbilityData`)

**스킬 트리도 스킬 포인트도 없다**(2026-08-23, `docs/design_combat_rework.md` 6절). 그건 빌드
최적화 게임이고, 켄시·림월드의 매력은 **캐릭터를 고르는 것이 아니라 상황을 관리하는 것**이다 —
스킬 트리가 늘리는 결정은 전투 중의 결정이 아니라 **창을 열고 점을 찍는 결정**이다.

- **능동은 폰이 아니라 장비가 준다** — `WeaponData.Ability` · `ArmorData.Ability`. 폰에 슬롯을
  두면 *"어느 폰에게 무엇을 배울까"*가 폰 수만큼 늘어나는 잡일이 되는데, 장비가 주면 **갈아입히는
  것이 곧 역할을 바꾸는 것**이라 이미 있는 조작으로 끝난다. 성장은 `CombatXp` 그대로 — **쓰면 는다.**
- **JSON 장비는 `abilityId`로 가리킨다**(`Resources/Data/Abilities/`의 에셋 이름) — 런타임 생성이라
  SO를 참조할 수 없다(`LoadoutData.ItemId`·`MerchantPoolEntry`와 같은 규약). **오타는 콘솔에 적는다** —
  안 적으면 *"방패를 들었는데 칸이 안 뜬다"*가 된다.
- **`AbilityUser`가 폰마다 붙는다**(`UnitBrain.Awake`, 세력을 안 가린다 — 장비에서 파생되므로
  안 찬 폰은 목록이 비어 저절로 아무 일도 안 한다). 목록은 **장비가 바뀔 때만** 다시 모으고,
  **같은 능력을 두 번 담지 않는다**(중갑 네 벌이 다 도발을 주면 칸이 넷인데 쿨다운은 하나라
  **눌러도 세 칸이 회색인 채로 남는다**).
- **아무도 안 걸려도 쿨다운은 돈다**(사용자 결정). 한때 헛친 것은 안 물렸는데, 그러면 **걸릴
  때까지 눌러 보는 것이 최선**이 되어 *언제 쓰느냐*가 결정이 아니게 된다 — 그 결정을 만들려고
  능동으로 둔 것이다. **다만 스탯은 안 는다**(헛친 것은 아무 일도 안 일어난 것이라 배울 것도 없다).
- **효과는 종류마다 제 주인이 있다**(`Taunt`) — `AbilityUser`에서 분기하면 능력이 늘 때마다
  그 파일이 전투 규칙을 알게 된다.

**도발 — 새 전투 규칙이 아니라 `DetectNode`의 답을 덮어쓰는 것 하나다**(`FinishTarget`이 자동
표적에 예외를 뚫은 것과 같은 자리).

- **`DetectNode` 맨 위여야 한다.** 아래의 *"더 가까운 적으로 갈아탄다"*보다 뒤에 두면 도발한
  순간 옆의 다른 적이 더 가깝다는 이유로 **한 틱 만에 풀린다** — 붙들어 두는 것이 도발의 전부라
  그러면 능력이 아무것도 안 한 것이 된다.
- **`Target`과 따로 든다**(`UnitBlackboard.TauntedBy`/`TauntedUntil`). 표적에 바로 꽂기만 하면
  같은 이유로 다음 틱에 갈아탄다. 만료·죽음·기절은 **`Taunt.HolderOf` 하나**가 본다 —
  지우는 코드를 따로 두면 그 경로 중 하나를 반드시 빠뜨린다.
- **강인함이 인원과 범위를 정한다**(인원 = 1 + 강인함/40 · 범위 = 4 + 강인함/30 m). 이미 KO
  저항을 정하지만 **다른 축**이라 겹치지 않는다(`Social`이 설득과 흥정을 함께 정하는 것과 같다).
  *맞고 버티는 놈이 앞에 선다*가 스탯 이름 그대로 읽힌다.
- **가까운 N명이지 위험한 N명이 아니다** — 가까운 쪽이 예측 가능하고, 위험도를 재려면 그 정의가
  또 하나 늘어난다(전력? 남은 체력? 나를 노리는 중인가?).
- **패시브가 아니라 능동인 이유**: 늘 켜져 있으면 ① 탱커를 데려가는 순간 다른 전술이 사라지고
  ② *"도발 중"*이 화면에 안 보인다. 지속 + 쿨다운이라 **언제 쓰느냐가 결정**이 된다.
  도발당한 쪽은 `PawnStatusText`가 **`도발당함`**으로 적는다(그냥 "전투"면 저 놈이 왜 딴 데를
  놔두고 탱커에게만 달려드는지가 화면에 안 남는다).
- **적은 아직 안 쓴다** — 그릇(`AbilityUser`)은 붙어 있고 장비에 능력을 물리면 되지만, 적 BT에
  *언제 쓸까*를 판단하는 자리가 없다. 넣으면 도발이 일방적이지 않게 되는 대신 적 BT가 는다(미결).

**조작**: 단축키 **1~4**(`AbilityController` — `DraftController`처럼 **씬 배선이 없다**) ·
액션 바 클릭. **고른 폰 전부**가 각자 제 칸의 능력을 쓰고 **화면은 첫 번째 폰만** 보여준다
(소집이 이미 그 모양이다 — 화면은 대표 한 명, 명령은 전원). **칸은 폰마다 제 목록의 순서**라
같은 칸이 폰마다 다른 능력일 수 있다 — 전역 목록으로 모으면 방패를 안 든 폰의 칸이 비어
번호가 밀린다. 바의 **규격은 씬이 갖는다**(`DungeonColony → Create Ability Bar`), 런타임은
칸을 몇 개 켜고 무엇을 그릴지만 정한다. **쓸 것이 없으면 바를 통째로 끈다.**

## 몸의 눈금 — 켄시 값 (부위 100 균일 · 혈액 100)

**머리·가슴·배·팔·다리 전부 100**(`BodyPartSystem.InitBodyParts`), **혈액도 100**, 파괴는 **−100 고정**(`BodyPart.IsDestroyed`) → 무력화(0)에서 **꼭 그만큼 더** 맞아야 부위가 떨어진다(1:2, 켄시 그대로).

**부위의 무게는 HP가 아니라 `HitWeight`(머리 10 · 가슴 18 · 배 16 · 팔 각 13 · 다리 각 15 = 몸통 34% · 사지 56%)와 그 부위가 무엇을 하느냐가 정한다** — 코어(머리·가슴·배)는 나가면 쓰러지고, 팔이 나가면 못 때리고 다리가 나가면 못 걷는다. HP로 또 가르면 같은 것을 두 번 표현하는 셈이고, 실제로 그러면 *"가슴은 두 배로 질긴 데다 제일 자주 맞는다"*가 되어 다른 부위가 뜻을 잃는다. **HP가 균일한 지금 부위를 가르는 축은 사실상 `HitWeight` 하나다.**

전엔 부위가 30/50/40/25였다. 눈금이 1/3이라 **팔다리가 한 방에 무력화됐고**(25 HP ↔ 강철 대검 26) 파괴 문턱만 −100 고정이라 *무력화는 한 대, 절단은 다섯 대*라는 이상한 사이가 생겼다.

- **피해는 안 올렸다** — 무기(9~26) · 방어구 평탄 감소(1~9) · 상태이상 전부 그대로다. 그래서 **전투가 약 두 배 길어진다**(의도한 것 — 켄시식 난전).
- **대신 타격당 혈액 손실을 절반으로 줄였다**(`slashBloodFactor` 0.5→**0.25** · blunt 0.1→**0.05** · other 0.25→**0.125**). 혈액이 100 그대로인데 부위만 세 배로 질겨지면 **모든 전투가 출혈 KO로 끝나고 절단을 영영 못 본다**:

  | | 출혈 KO | 가슴 무력화(기대) |
  |---|---|---|
  | 예전(가슴 50) | 7.7대 | 6.4대 |
  | 부위 100 · 계수 그대로 | **7.7대** | 12.8대 ← 출혈이 늘 먼저 |
  | 부위 100 · **계수 절반** | 15.4대 | **12.8대** ← 부위가 먼저 |

  (강철 대검 26 기준. 무력화는 피격 가중치를 감안한 **총** 타격 수.)
- **몸통 비중이 곧 전투 길이다 — 쓰러뜨리는 것은 코어뿐이라서**(`IsCorePart`). 그래서 몸통을 50%(가슴 30 + 배 20)에서 **34%로 낮췄다**: 부위 HP를 100 균일로 올리고 나니 *팔 하나 무력화 38대 : 전투 13대*가 되어 **켄시의 상징인 절단·의족을 구조적으로 못 보는** 배치였다. 지금은 총 타격 수가 **가슴 21.4 · 배 24 · 다리 25.6 · 팔 29.6 · 머리 38.5**로 어느 하나가 압도하지 않는다(다리 > 팔 — 표적도 크고, 나갔을 때 못 걷는다는 뜻도 무겁다).
- **그래서 쓰러지는 것은 대개 출혈이다**(베기 15.4대 ↔ 가슴 21.4대) — 켄시도 난전에서 눕는 이유는 대개 실혈이고 부위 파괴는 그 뒤에 오래 두들겨 맞을 때 온다. **무기가 이 축을 가른다**: 둔기는 혈액 계수 0.05라 **부위로 눕히고**(뼈 몽둥이의 *"죽이기보다 눕히기에 낫다"* — 출혈로는 59대가 걸린다), 베기는 0.25라 **피로 눕힌다**. 부위 쪽을 먼저 오게 하려면 **`slashBloodFactor`를 더 내린다**(0.25 → 0.18이면 21.4대로 가슴과 나란해진다) — `HitWeight`를 도로 올리면 사지가 다시 안 상한다.
- **혈액은 강인함을 통과한 뒤의 피해에서 뺀다**(`actualDamage * bloodFactor`) — 그래서 강인함이 높아도 부위와 혈액이 **같은 비율로** 늦춰진다.
- **부위 축만 ×3으로 같이 올린다**(평균 부위 HP 31→100): `partRegenPerSec` 0.8 · `RestNode` 부위 3 · `Treatment.BasePartHeal` 38 · `coreKoDepth` 30 · **`WorldBattle`이 주는 피해**(30~60 · 9~27 — 그건 무기 피해가 아니라 *"진 쪽이 이만큼 다친다"*는 결과라, 안 올리면 **진 원정대가 멀쩡히 걸어 나온다**).
- **혈액 축은 전부 예전 값 그대로다** — `maxBlood` 100 · 부위별 `BleedRate` 0.2~0.8(지속 출혈은 `clotSeconds` 30초가 끊으므로 혈액이 100인 이상 예전 페이싱이 맞다. 줄이면 단일 부상이 아무것도 아니게 된다) · `bloodRegenPerSec` 0.2 · `RestNode` 혈액 2·캡 1 · `Treatment.BaseCapHeal` 8 · 아사 2. `HitWeight`와 비율로 재는 것(`deathBloodRatio`·`wakeBloodRatio`·`FleeBloodRatio`)도 그대로.
- **`maxBlood`·혈액 계수·`coreKoDepth`·회복률은 `[SerializeField]`라 프리팹이 값을 들고 있다** — 코드 기본값을 고쳐도 **이미 있는 프리팹에는 아무 힘이 없다**(`EventManager.checkInterval`이 씬에 10으로 박혀 있던 그 함정). 폰 프리팹 26종은 같이 고쳤다. **부위 HP와 `BleedRate`는 런타임 생성이라**(`InitBodyParts`) 코드만 고치면 된다.

## 치료 — 다친 폰을 다른 폰이 돌본다

부상은 누워 있으면 저절로 낫는다(`RestNode`: 혈액 2/s · 캡 1/s · 부위 1/s). 그건 시간이 지나는 것이지 누가 무엇을 한 것이 아니라, **부상이 사건이 되지 못했다.**

- **침대는 회복을 얹는 것이지 조건이 아니다** — **폰을 직접 우클릭**해도 치료한다(`TreatJob(patient, manual)`). 전투 직후 쓰러진 사람을 그 자리에서 돌보는 것이 침대까지 끌고 가는 것보다 급하다. **자기 자신도 된다**(`[스스로 치료한다]`, `SelfPenalty` 적용) — 누운 채 저절로 도는 `SelfTend` 토글과 **다른 축**이다(토글은 "알아서 해라", 이건 "지금 해라"). **침대에 누운 환자면 침대 쪽 일감을 쓴다**(`Bed.FindOccupiedBy`) — 새로 만들면 같은 사람에게 둘이 붙고 침대가 제 일감을 지울 때 이건 안 지워진다. **기절한 폰은 남도 자기도 못 돌본다.**
- **우클릭으로 시킬 수도 있다** — `Bed.RequestTreatBy(doctor)` → `JobManager.ReserveFor`(등록 + 그 폰 앞으로 예약). `RequestJob`이 **이 폰이 예약한 일감을 먼저** 돌려주므로(`FindReserved`) 추첨을 건너뛴다. **작업 설정(on/off)도 안 본다** — 손으로 시킨 일은 "이 작업을 맡길까"의 결과가 아니라 지금 이 순간의 지시다(자원 노드 직접 배정과 같은 규칙). **새로 만들지 않고 있던 일감을 넘긴다**(침대가 주인이라 하나 더 만들면 같은 환자에게 둘이 붙는다), **이미 하고 있으면 안 뺏는다**(약만 버려진다).
- **`Bed`가 일감을 낸다**(`TreatJob`, `JobCategory.Medical`). 다친 폰 자신이 내면 "누가 등록을 지우는가"가 애매해진다 — 기절하거나 죽으면 스스로 못 지운다. 침대는 자리를 아는 유일한 물건이고, 작업대가 제작 주문을 내는 것과 같은 자리다.
- **누워 있을 때만** 생긴다. 환자가 돌아다니면 의사가 쫓아다녀야 하고, 침대 배정은 이 게임에서 이미 "쉬어라"라는 명령이다. 플레이어 세력만 돌본다.
- **한 회차 = 약 하나.** 시간을 재서 조금씩 얹는 대신 회차로 끊는 이유는 그래야 **소모품을 쓰는 자리**가 생기기 때문이다. 나을 것이 남았으면 `Bed`가 다음 회차를 다시 건다.
- **자기 자신은 못 고친다**(`CanAssignTo`) — 누운 폰이 제 일감을 집으면 침대에서 일어나 침대 옆으로 걸어간다.
- **`BodyPartSystem.Treat(partHeal, capHeal)`** — 부위 HP + **`BloodCap` 복구**(자연 회복이 못 하는 것) + **즉시 지혈**(`StopBleeding` — `LastWoundTime`을 과거로 민다). 혈액은 `degradeCap: false`로 채운다(캡을 되돌리는 일인데 깎으면서 되돌리면 제자리걸음).
- `NeedsTreatment`는 **파괴된 부위를 안 센다** — `HealBodyParts`가 건너뛰므로 세면 영원히 안 끝나는 일감이 된다(의족은 후유증 축의 일).

**의료용품은 등급(`ItemQuality`)이 아니라 별개 아이템이다**(`MedicineData`, JSON `"type": "medicine"`). 등급은 같은 물건이 잘 만들어졌느냐의 축인데, 찢은 천과 구급낭은 그 관계가 아니다. 따로 두면 레시피·재료·값이 각자 붙는다.

| ItemId | 이름 | 효능 | 속도 | 만드는 법 |
|---|---|---|---|---|
| (없음) | **맨손** | 0.4 | 0.55 | — 도구를 요구하면 물자가 끊길 때 치료가 통째로 멎는다 |
| `med_rag` | 넝마 | 0.75 | 0.8 | 천 1 → 3 (노동) |
| `med_bandage` | 붕대 | 1.0 | 1.0 | 천 2 → 2 (노동) |
| `med_poultice` | 약초 습포 | 1.6 | **0.75** | 약초 3 + 붕대 1 → 2 (연금) |
| `med_kit` | 구급낭 | 2.3 | 1.4 | 붕대 3 + 약초 2 + 정수 1 (연금) |

효능과 속도를 **따로** 둔 이유: 약초 습포처럼 **잘 듣지만 손이 많이 가는** 것이 있어야 고르는 일이 된다. **가장 좋은 것을 쓴다** — 아껴 쓰면 애써 만든 구급낭이 영영 상자에 남는다. 무엇을 쓸지는 **무엇을 쟁여 두느냐**로 이미 조절된다.

**약은 손에 든 것만 쓴다**(`Treatment.BestInBackpack`/`ConsumeFromBackpack`). 창고 것을 원격으로 소모하면 붕대가 손에 없는데 감기는 꼴이 된다. 그래서 `TreatJob`은 **2-phase**다(`ConstructionJob`과 같은 패턴): 배낭에 약이 있으면 바로 환자에게, 없으면 **창고에 들러 챙긴 뒤**(한 번에 5개 — 회차마다 왕복하면 붕대 하나 감는 데 맵을 가로지른다) 환자에게. 남은 것은 다음 회차에 그대로 쓰이고, 다 낫고 남으면 `UnloadJob`이 창고로 돌려놓는다. **배낭에 있으면 더 좋은 것을 찾아 창고에 가지 않는다** — 그동안 환자는 피를 흘린다.

**자가치유(`WorkSettings.SelfTend`, 기본 끔)는 일감이 아니라 `RestNode` 안에 있다.** BT 순서가 `Rest → … → Work`라 침대에 배정된 폰은 `RestNode`에서 Running으로 멈춰 **`WorkNode`까지 가지 않는다** — 일감으로 만들면 아무도 못 집는 일감이 된다(림월드도 자가치유는 누운 채로 한다). 누워 있는 사람은 창고에 손을 못 뻗으므로 **제 배낭에서만** 약이 나오고, `Treatment.SelfPenalty`(0.7)가 붙는다 — 한 손으로 안 보이는 곳을 아픈 채로 싸맨다. **기본이 꺼져 있는 이유는 약을 축내서다**(림월드와 같다) — 의료가 낮은 폰이 구급낭을 헐어 쓰는 것보다 의사를 기다리는 편이 대개 낫고, **켜진 줄 모르는 채 물자가 새는 것**이 가장 나쁘다. 켜는 자리를 둔 이유는 **의사가 없을 때**(혼자 다니는 방랑자, 원정에서 돌아온 폰). P키 패널에서 짐내림 옆.

**회복량·속도·약 고르기는 `Treatment`가 단일 출처다** — 치료하는 길이 둘(의사·자가)이라 양쪽에 따로 적으면 반드시 어긋난다.

`StatName.Medicine`(의료)이 회복량과 속도를 함께 정한다(`0.5 + 의료/100`) — 그전까지 이 스탯은 이름과 설명만 있고 **아무 데서도 안 읽혔다.**


## 지각 기억 — 보이는 동안만 알고, 놓치면 찾으러 간다 (2026-10-18)

**전에는 반대였다 — 한번 잡은 표적을 절대 안 잊었다.** 훑기(`FactionScan`)도 시야(`Vision`)도 바위를 몰랐고, `DetectNode`는 새 후보가 없으면 든 표적을 그대로 쥐었다(놓는 조건은 *칠 수 없게 됐나* 하나). 그래서 굴 모퉁이를 돌아도, 맵 끝까지 달아나도 정확히 따라왔다.

- **보이나는 `Vision.CanSee` 하나** — 반경(`RangeFor` · 밤 · 불빛 · 밤눈) 안이고 사이 칸에 바위가 없을 것(`Vision.SightClear` · `RockMap.IsRock` — 안개와 같은 판정). **지은 벽은 안 막는다** — 안개도 안 막으므로, 한쪽만 바꾸면 *"화면엔 보이는데 폰은 못 본다"*가 생긴다.
- **잡는 것은 보이는 것만**(`FactionScan.NearestSeen`). 도주 · 수적 보너스 · 도발의 훑기는 예전 그대로(벽 너머도 센다).
- **든 표적은 아는 동안만 든다**(`DetectNode.Knows`) — 보이거나(놓을 때는 반경 ×1.2, 끝에서 흔들리지 않게) · 도발 · 뚫는 벽 · **사람이 지목한 것** · 방금 나를 친 놈(15초 — *아픔은 눈이 아니다*). 모르게 되면 놓는다(근접 자리 · 공격 타이머도 — `LoseSight`).
- **보이는 동안은 시간 제한 없이 쫓는다**(사용자: *"도망치는데 거리가 안 벌어지면 끝까지 따라오는 게 맞다"*). 시계는 안 보일 때만 돈다.
- **경계 상태**(`bb.Alert`) — 평온 → 교전 → (놓침) 수색 → 평온. `Engaged`는 `Alert == Combat`을 읽는 이름으로 남았다.
- **수색**(`SearchNode` — 전투 묶음 바로 뒤) — 마지막으로 본 자리(`LastSeenPos`)까지 가서(못 가면 닿은 데까지) 6초 둘러본다(`bb.TickDelta`). 그동안에도 감지가 매 틱 돌아 다시 보이면 교전. **잊는 것은 거리 + 시간 중 먼저 오는 것** — 안 보인 지 30초(`GameTimeManager.Elapsed`) · 마지막 자리가 감지 범위 ×3보다 멀다.
- **찾으러 안 가는 폰** — 소집(자리를 지킨다 · `DraftLeash` 그대로) · 도주 성향 · 떠나는 중(`MaySearch`).
- **원한**(`bb.Grudges`, 사용자: *"이미 적대 관계가 됐는데 시간이 지났다고 풀리는 경우"*) — 나를 친 놈은 세력이 중립이어도 적이다. 전에는 15초만이었고 칸도 하나였다. **누구인가만 든다** — 보여야 치고, 먼저 노리지도 않는다(가까운 순). 반격 성향 · 소집도 원한은 본다(이미 시작된 싸움이다) · 도주 성향은 안 본다. 시간으로 안 풀린다 — 그놈이 같은 편이 되면 안 걸리고, 내가 죽거나 세력이 바뀌면 버린다(`ClearMemory`).
- **전투 묶음은 한 벌**(`UnitBrain.AddFight` — 감지 → 능동 → 교전 → 수색). 네 트리(방랑자 · 하수인 · 가축 · NPC/적)가 각자 조립하던 것을 모았다.
- **진단** — `DungeonColony/Debug/Perception Log`를 켜면 상태가 바뀔 때만 `[지각] 이름: 놓침 (… — 바위에 가림 · 마지막 자리 (x,z))` · `교전→수색` · `수색→교전 (… 다시 봄)` · `수색→평온 (못 찾음 6초)`.
- **없는 것** — 소리(들었다)는 없다(소리 축이 없다). 시야는 보인다/안 보인다 둘이고 *흐릿하게 보임*은 없다.

## 거리 유지 — 원거리는 붙으면 물러나고, 벌어지면 한 발 쏠 때까지 선다 (2026-10-20)

사용자: *"적이 쫓으면 계속 물러나야 돼 — 어느 정도 거리가 될 때까지. 거리가 되면 쏘기 전까지는 물러나면 안 되는 거지. 상대가 빠르면 내가 맞는 거고, 느리면 내가 쏘는 거고, 같으면 평생 튀어."* — **빠르기를 따로 셈하지 않는다.** 시간 상한도 없다.

- **답은 `Kiting` 하나**(`Combat/Kiting.cs` · 상태 `bb.Kite`) — `FightNode`의 사거리 안 갈래 앞에서 묻는다.
- **언제** — 원거리 무기 · 소집 아님 · 표적이 폰. 거리 < `max(3m, 사거리×0.35)`면 물러나기 시작해 **사거리×0.7**까지 걷는다(활 9m → 3.2m에서 시작 · 6.3m에서 선다).
- **서면 한 발 쏠 때까지 안 움직인다**(`Hold` → `CombatHandler.LastStrikeTime`). 쏜 뒤에도 붙어 있으면 다시 물러난다.
- **물러나는 동안 전투는 켠 채다** — 장전은 걸으며 찬다. 조준만 걸음에 풀리므로 서는 순간 곧 쏜다.
- **자리** — 표적 반대쪽 · ±45° · ±90° 순. 설 수 있고(`FindWorkableNear`) · 곧게 뚫렸고(`LineIsClear` — 바위·얇은 벽) · 지금보다 멀고 · 거기서 표적이 보이는(`Vision.SightClear`) 자리. 걷는 동안 1.5초마다 다시 고른다(적이 돌아 들어온다).
- **몰리면 제자리에서 쏜다** — 자리가 없거나, 한 걸음(1.5초)에 0.5m도 못 움직였으면. 2초 뒤 다시 찾는다.
- 안 바뀌는 것 — 소집(자리를 지킨다) · 근접 · 건물 표적 · 이동 명령(트리 위).
- **진단** — `DungeonColony/Debug/Kiting Log` → `[거리] 이름: 붙었다 … 물러난다` · `벌어졌다 … 쏠 때까지 선다` · `쐈다` · `몰렸다(…)`.

## 기절한 폰은 아무도 안 때린다 — 지목한 하나만 예외

`BTTargetUtil.IsAttackable`이 기절(`IsKnockedOut`)·시체를 **모든 자동 경로**(탐지·교전·반격)에서 뺀다. **KO가 사형선고가 아니라 회복 가능한 상태**여야 하기 때문이다(켄시식) — `BodyPartSystem.UpdateKnockOutRecovery`가 최소 시간 + 코어 부위 회복 + 혈액 기준으로 일으켜 세운다.

**언데드는 기절하지 않는다 — 쓰러지는 구간 없이 그 자리에서 부서진다**(`UnitData.IsUndead`(해골) ∥ **일으켜진 몸**(`UnitBrain.Rise`) → `UnitBrain.IsUndead`). 기절은 *의식을 잃는 것*이라 해골에게도, 이미 한 번 죽어 일어난 몸에게도 성립하지 않는다. **갈리는 자리는 `BodyPartSystem.KnockOut` 하나** — 기절로 오는 길이 셋인데(혈액 임계 · 코어 부위 깊이 · 강인함 굴림) 각자 앞에서 물으면 하나가 빠져 *가끔* 기절하는 해골이 남는다. 그래서 **언데드는 혈액 0에서 부서진다**(사람이 −30까지 버티는 구간이 통째로 없다).

**딸려 오는 것**: 붙잡기·회유·몸값이 전부 기절에서 시작하므로(`PawnCarry.CanCarry`는 남이면 기절을 요구한다) **언데드는 산 채로 못 잡는다.** 해골을 갖고 싶으면 붙잡는 것이 아니라 **뼈로 빚는다**(핵 소환 25) — 뼈로 닫히는 고리와 오히려 맞물린다. 일어난 동료를 되돌릴 길이 없다는 것도 같은 자리다: **그래서 태우는 것이 값을 갖는다.** 되돌리려면 종족 에셋의 체크 하나(`IsUndead`)를 끄면 된다.

그래서 **때려눕힌 적은 내버려 두면 일어난다.** 확실히 죽이려면 우클릭 **[공격한다]**(문구는 서 있는 적과 같지만 안에서 `FinishWith`로 갈린다) — `UnitBlackboard.FinishTarget`에 그 대상을 지목하면 `IsAttackable(go, bb)`가 그 **하나만** 통과시킨다. 규칙을 고치는 대신 예외를 뚫는 이유: 자동으로 뚫리면 KO 회복이 사실상 사라지고, 그렇다고 길이 아예 없으면 이겨도 전투가 안 끝난다.

**예외는 한쪽 방향뿐이다** — 지목은 `MoveController`(플레이어 우클릭)에서만 붙으므로 **쓰러진 우리 폰은 적에게 여전히 안 맞는다**. 지목은 대상이 죽거나(`FightNode`) 다른 명령이 오면 거둬진다.

**쓰러진 놈은 막지도 피하지도 못한다** — `CombatHandler.Measure`가 `IsDown`이면 둘 다 0을 돌려준다. 방어도 회피도 능동적인 동작이다. 회피를 `Evasion`으로 굴리면 회피 높은 폰은 기절해서도 잘 안 맞아 **눕힌 보람이 사라진다**(빗맞음을 넣고 싶으면 방어자 스탯이 아니라 고정 확률이어야 한다).

**누가 죽든 시체로 남는다 — 내 폰도**(2026-08-15). 한때 플레이어 세력만 그 자리에서 파괴했는데, 그 경로는 `BecomeCorpse`를 안 거쳐 **입고 있던 장비와 배낭이 통째로 증발했다**(원정 나간 폰이 죽으면 지고 있던 짐까지). 죽음이 *"장비를 되찾으러 가는 일"*이 되려면 몸이 남아야 한다 — `Corpse.WasPlayer`가 원래 그걸 상정하고 있던 자리다. 갈랐던 이유였던 "내 폰 시체가 쌓인다"는 **치우는 길**로 풀 일이지 몸을 없애서 풀 일이 아니다.
- **명부·무리 관리·원정 편성에서는 저절로 빠진다** — 셋 다 `Faction.IsPlayer`로 거르는데 `BecomeCorpse`가 `Faction` 컴포넌트를 지우기 때문이다. **선택은 따로 뺀다**(`SelectionManager.PruneSelection`이 `Corpse`를 본다) — 파괴되지 않으므로 `== null`로는 안 걸리고, 안 빼면 우클릭 명령이 송장에게 나간다.
- **혈액은 0이 아니라 −30에서 죽는다**(`deathBloodRatio` −0.3 × `maxBlood` 100, 켄시식 — 기절을 건너뛴 즉사를 막는다). 그래서 쓰러진 폰은 그 사이에 치료하면 살아난다. "시체가 갑자기 사라진다"의 정체가 이것이었다 — 사라진 것은 시체가 아니라 **아직 살아서 피 흘리던 내 폰**이었고, 죽는 순간 파괴됐다.
- **시체는 삭는다 — 그러나 사라지지는 않는다**(`CorpseStage`: 신선 1일 → 썩음 3일 → **뼈(영구)**). 단계가 곧 **할 수 있는 일**이고, 그것이 "언제까지 치워야 하나"를 만든다. 시각은 `GameTimeManager.Elapsed`로 잰다(배속·일시정지가 그대로 반영된다). 단계가 바뀌면 **색으로 알린다**(MPB — 시체마다 머티리얼 인스턴스가 생기지 않게).
  - **뼈가 저절로 안 없어지는 것이 요점이다.** 그게 매장·화장이 있어야 할 이유이고, **교단·망자 습격이 오면 맵에 남은 시체가 일어난다**(`Necromancy`, 2026-08-19). 그래서 **치우는 일이 잡일이 아니라 방어**가 된다 — 새 이벤트를 안 만들고 기존 습격에 얹으므로 습격 빈도는 안 는다.
- **치우는 길은 셋이다 — 무엇이 남느냐가 다르다**(`ButcherJob` / `Grave` / `Pyre`).

  | 길 | 값 | 남는 것 |
  |---|---|---|
  | **도축** | 공짜 + 폰의 시간 | 고기·가죽·뼈 — 다만 **나올 것이 있는 몸에만** 통한다(`Butchering.HasYield`) |
  | **매장**(무덤 2×1, 돌 18) | 그 **칸을 영영 먹는다** | 몸이 남는다 — **다시 파낼 수 있고**, 나중에 교단이 파낼 수도 있다 |
  | **화장**(화장터 2×2, 돌 40 + 태울 때마다 목재 5) | 시간(60초) + 목재 | 아무것도 — **되돌릴 수 없다** |

  **사람도 가를 수 있지만, 그게 무덤을 없애지는 않는다** — 도축은 *동료의 시신에 하는 일*로는 성립하지 않고(규칙 기본값이 적대 세력만인 것도 그래서다), 무엇보다 도축은 **몸을 없애 주지만 그 대가로 뼈를 남긴다**. 무덤과 화장터가 갈리는 것은 값이 아니라 **끝맺음**이다: 무덤은 싸고 즉시지만 미루는 것이고, 화장은 값을 치르고 끝내는 것이다. **그 차이는 이제 값을 갖는다** — 묻은 몸은 **무덤을 파는 세력**(교단)만 일으키고, 태운 몸은 어느 쪽으로도 안 돌아온다(`Necromancy`). 치울 길을 **그 기능보다 먼저** 붙여 둔 이유가 그것이다(치울 길이 없는 채로 시체가 일어나면 그건 선택이 아니라 사고다).
  - **묻히면 시간이 멈춘다**(`Corpse.SetBuried` — `DiedAt`을 옮겨 나이를 얼린다. 파내면 거기서 이어 삭는다). 땅속에서도 삭게 두면 무덤이 *"보이지 않는 곳에 쌓아 두는 자리"*가 된다. 묻는 동안 렌더러·콜라이더를 끈다(**`CharacterController`는 빼고** — 그것도 `Collider`라 한꺼번에 훑으면 딸려 온다).
  - **유품은 안 태운다** — 태우는 것은 몸이지 물건이 아니고, 안 뒤지고 올려놓았다고 장비가 사라지면 조용한 손실이다(`ButcherJob`과 같은 규칙). 발밑에 떨궈 운반 축(H)에 올린다. **무덤은 같이 묻는다** — 파내는 길이 있으니 잃는 것이 아니다.
  - **유품에 답하는 것은 `Corpse.SpillBelongings` 하나다 — 배낭과 *차고 있던 장비* 둘 다 내놓는다.** 장비는 격자를 안 먹으므로(시체 창이 장비 열을 따로 그린다) **배낭만 훑으면 무기·갑옷이 시체와 함께 조용히 사라진다** — 도축도 화장도 마지막에 몸을 없애기 때문이다. 실제로 `ButcherJob`과 `Pyre`가 각자 배낭만 훑고 있었고, 화장터에는 *"장비가 사라지면 조용한 손실"*이라고 **적혀만 있었다**(2026-08-16). 답을 시체에 둔 이유: 부르는 곳이 둘이고 앞으로 늘 텐데 각자 적으면 하나가 반드시 장비를 빠뜨린다. **무덤은 안 부른다** — 같이 묻고 파낼 수 있어서 잃는 것이 아니고, 그것이 무덤과 화장을 가르는 축이다.
  - **화장터에는 폰이 안 붙는다.** 시체를 올려놓는 것 자체가 이미 사람이 업고 와서 하는 일이고, 불을 지키고 서 있는 것은 아무것도 안 정한다(핵이 우리에 가둔 하수인을 저 혼자 지배해 가는 것과 같은 자리) — 그래서 **새 일감도 새 작업 카테고리도 없다**. 연료는 **불을 붙일 때 한 번** 낸다(매 틱 조금씩 빼면 "반쯤 탄 시체"라는 상태가 생기는데 그걸 표현할 데가 없다). 모자라면 멈추고 **줄에 이유를 적는다**(`BlockedReason`).
  - **건물이 없어지면 시체가 도로 나온다**(`OnDisable` → `Exhume`/`Eject`) — 안 꺼내면 묻어 둔 몸이 건물과 함께 조용히 사라진다.
- **죽은 자가 일어난다 — `Necromancy`**(2026-08-19). **치우지 않은 시체가 습격의 재료가 된다.** 교단·망자가 쳐들어오면 맵에 널브러진 시체가 **그 자리에서** 일어난다 — 습격이 가장자리에서 걸어 들어오는 것이 아니라 **거점 한복판에서** 시작된다.
  - **일으키는 것은 세력이 답한다**(`FactionData.RaisesDead` / `ExhumesGraves` / `RisenBones` — `AcceptsRansom`·`ForHire`와 같은 자리). **습격이 오는 길이 둘**이라(이벤트 추첨 · 지도에서 걸어온 무리) 이벤트 에셋에 적으면 **지도에서 온 교단은 시체를 그냥 지나친다** — 플레이어에게 그 둘은 똑같이 '교단이 몰려온 것'이다(구원이 양쪽에 다 붙는 것과 같은 이유). 그래서 **실제로 쳐들어온 폰들의 소속을 묻는다**(`Necromancy.OnRaidArrived(arrivals)`) — 배선을 하나 빠뜨려 조용히 아무 일도 안 일어나는 자리가 안 생긴다.
  - **무엇이 되는지는 시체의 단계가 정한다.** **살점이 남았으면(신선·썩음) 그 몸이 그대로 일어난다** — 이름·스탯·특성·**차고 있던 장비까지**(`UnitBrain.Rise`). 프리팹이 필요 없고, 무엇보다 **죽은 동료가 내가 입혀 준 갑옷을 입고 걸어온다**. **뼈만 남았으면 해골이 선다**(`RisenBones`) — 그 모양은 더 이상 그 사람이 아니므로 몸을 없애고, **유품은 `Corpse.SpillBelongings`가 내놓는다**(도축·화장과 같은 규칙).
  - **`UnitBrain.Rise`는 `BecomeCorpse`의 짝이다.** 저쪽이 **끄기만 하고 아무것도 안 지운** 덕에(*"되살릴 일이 생기면 그대로 되돌릴 수 있다"*고 적혀 있던 그 자리다) 도로 켜면 그 사람이 선다. 되돌릴 것 넷: **`Corpse` 제거**(안 지우면 업기·도축·무덤이 산 사람을 시체로 본다) · **`Faction` 재부착**(`BecomeCorpse`가 컴포넌트째 지웠다) · **역할과 `Merchant` 제거**(안 지우면 일어난 상인이 제자리를 지키고 서서 **죽은 자와 거래가 된다**) · **몸**(`BodyPartSystem.Rise` — 혈액이 사망 비율 −30에 있고 부위가 **파괴**돼 있어, 켜기만 하면 다음 틱에 `CheckBloodState`가 다시 죽인다. `HealBodyParts`가 건너뛰는 파괴 부위까지 되돌리는 유일한 자리다 — 일으키는 것은 치료가 아니라 죽음을 되돌리는 일이다). BT·성장 잠금은 `ChangeFaction`과 **같은 식**이어야 한다. **그리고 `_bb.Faction` 캐시를 같이 갈아 끼운다** — `UnitBlackboard`가 `Awake`에서 한 번 잡는 참조인데 `BecomeCorpse`가 그것을 파괴하므로, 새로 붙이기만 하면 블랙보드가 **파괴된 옛 참조**를 들고 `DetectNode`가 `myFaction == null` 가지로 빠져 **일어난 것이 아무도 안 때린다**(`ChangeFaction`은 같은 컴포넌트의 값만 갈아 이 함정을 안 밟는다).
  - **일어난 몸은 물들인다**(`Corpse.Tint` — 삭을 때 색으로 알리는 것과 같은 자리). 모양이 그대로라 안 물들이면 **내 폰과 눈으로 구별되지 않는다.**
  - **사람 손에 있는 것은 안 일어난다** — 업고 가는 중 · 도축대에 눕혀 놓은 것 · **화장터에 올려 불을 붙인 것**. 그 자리들은 저마다 몸을 붙들고 있어 자세·자리·일감이 한꺼번에 어긋나고, 무엇보다 불 위에서 일어나는 것은 화장을 *끝내는 길*로 둔 취지와 정반대다.
  - **부패 눈금**: 신선 ~1일(1배속 실기 30분) · 썩음 1~3일 · **뼈 3일~영구**(`Corpse.FreshDays`/`RottenDays`, 하루 1800초). **습격 주기(1~3일)와 겹치게 잡은 값이다** — 2일·4일이던 시절엔 신선한 몸이 실기 한 시간이라 싸움 뒤에 서두를 이유가 없었다. 시험은 `DungeonColony → Debug/Age Corpses → 썩음 / 뼈`(`Corpse.SetAge` — 나이를 옮기는 문은 `SetBuried`와 여기 둘뿐이다).
  - **묻힌 것은 무덤을 파는 세력만**(교단 `ExhumesGraves`, 망자는 아니다). 그것이 무덤에 값을 준다 — 망자 습격은 막아 주지만 교단에는 안 통하고, 화장만이 어느 쪽으로도 안 돌아오게 한다.
- **도축·도축대 세부는 `docs/jobs.md` "시체를 치운다 — 도축과 도축대"로 내렸다.** 밖에서 어기기 쉬운 것만 여기 남긴다:
  - **몸에서 나오는 것은 종족이 든다**(`UnitData.ButcherYield`/`BoneYield`, **갈라야 나온다**), **지니던 것은 `LoadoutData.Loot`**(태어날 때 배낭에 들어가 죽으면 그 자리에 남는다). **시점이 그 둘을 가르는 축이다.**
  - **단계 규칙은 `Butchering` 하나가 답한다**: 신선=전부 / 썩음=**음식만 빠진다**(`is FoodData`) / 뼈=뼈만.
  - **뼈가 고리를 닫는다** — 도축이 내놓는 `Res_Bone`이 소환 비용(고블린 12 · 해골 25) · 연구(`Res_Bonecraft`) · 무기(`wpn_bone_club`)로 돌아, **치우는 것이 잡일이 아니라 생산 라인의 앞단**이 된다.
  - **`JobCategory.Butcher`가 큐를 탄다**(제작 뒤 · 운반 앞). 자동이 동의 없이 벌어지지 않는 것은 큐를 막아서가 아니라 **규칙(`ButcherBill`)을 사람이 먼저 걸기** 때문이다.
  - **산 채로 쓰러진 것도 가른다** — 판정은 `Butchering.CanButcherAlive` 하나(우클릭 메뉴와 일감이 같이 묻는다). **가는 사이에 깨어나면 그만둔다.**
  - **한 몸에 일감은 하나**(`JobManager.HasButcherJobFor`) — 문이 둘이라(우클릭 · 규칙) 각자 걸면 두 폰이 같은 곳으로 걸어간다.
  - **상판에 눕힌 몸은 `SetSleeping`으로 붙든다** — 기절은 `IsSleeping`이 아니라 회전만 눕힌 상태라, 안 재우면 `PawnMover`가 매 프레임 중력을 먹여 **상판에서 끌어내린다.**

**시체는 죽은 그 순간에서 멈춘다** — `BecomeCorpse`가 `UnitBrain`·`PawnMover`·`CombatHandler`에 더해 **`BodyPartSystem`·`StatusEffectSystem`도 끈다**(안 끄면 시체의 혈액이 계속 줄거나 차고, 계속 불탄다). **`Faction` 컴포넌트는 지우되 소속은 `Corpse.Faction`이 기억한다** — 지우는 건 자동 탐지(`OverlapSphere` + `GetComponent<Faction>`, `enabled=false`로는 못 막는다)를 끊으려는 것이지 잊자는 뜻이 아니다. 그래서 **"모르는 것은 플레이어가 아니다"** — `faction == null`을 플레이어처럼 대하면 시체가 그 구멍으로 들어온다(허기 바가 떴었다).

### 전투 — 피해 · 능동 능력 · 몸 · 치료 · 기절과 시체

**세부는 `docs/combat.md`**(원소별 효과 · 눈금 표 · 회피 셈 · 원거리 셋 · 빗맞음 · 도발 · 부위 HP 셈 · 의료용품 표 · 부패 단계 · 도축/매장/화장 · `Necromancy`). 여기 남기는 것은 밖에서 어기기 쉬운 것뿐이다.

```
DamageType:  물리 Slash / Pierce / Blunt        ← 갑옷이 막는다
             원소 Fire / Water / Earth / Lightning / Arcane / Dark / Holy  ← 저항이 막는다
```

- **축은 하나다** — 2026-08-23에 `DamageCategory` × `DamageElement` 2D를 접었다(**물음 하나에 답이 둘**이었다). 저항은 `ArmorData.Resistances` + `UnitData.Resistances`가 더해지고, **갑옷의 `DamageReduction`은 물리에만**. **신성 ×2는 저항표가 아니라 `UnitBrain.IsUndead`가 답한다**(표에 적으면 **일으켜진 몸**은 사람 종족이라 성물이 안 듣는다). 어느 스탯이 자라는지는 **`UnitStats.StatFor(WeaponData)` 하나**(`Type`만 보면 불과 암흑이 같아진다).
- **`StatName`·`DamageType`·`JobCategory`·`BuildCategory`·`MerchantType`은 정수로 직렬화된다 — 값은 반드시 꼬리에 붙일 것.** 중간에 끼우면 저작 에셋이 통째로 밀린다(`CombatStance.Retaliate`를 꼬리에 넣은 이유다).
- **안 맞는 것은 한 물음이라 같이 잰다 — `CombatHandler.Measure`.** 막기와 회피를 따로 굴리면 **총량에 천장을 씌울 자리가 없다**(둘 다 멀쩡해 보이는데 합이 96%가 됐고, 키운 폰은 약한 적에게 영영 안 맞았다). **총량을 먼저 정하고 몫으로 나눈다**(`maxAvoidChance` 0.6). **쓰러진 놈은 막지도 피하지도 못한다.**
- **원거리 스탯 셋은 하는 일이 하나씩이다** — **인지력**=맞나 + 움직이는 표적 + **사거리** / **정밀사격**=아군 오사 확률 그것 하나 / **무기 숙련**=재장전(원거리 피해에서는 빠졌다 — 재장전이 곧 DPS라 둘 다 주면 그 축이 다른 선택을 덮는다). **`UnitBlackboard.AttackRange`가 프로퍼티인 것이 요점이다** — **장착할 때 한 번 구워 두면 키운 인지력이 영영 안 붙는다.** 빗맞음은 **부채꼴**(반각 20°, 표적까지)이고 **세력을 안 가리며**, **겨눈 표적은 반드시 `exclude`한다**(안 빼면 표적 자신이 제 몫의 빗맞음 대상이 된다).
- **표적이 없으면 싸우는 중이 아니다**(2026-09-11) — `CombatHandler.Update`가 매 프레임 `BTTargetUtil.IsAttackable`로 묻고 아니면 스스로 `ExitCombat`한다. 전에는 끄는 자리가 `FightNode` **하나**였는데 **그 노드는 탐지가 성공해야 돈다**: 마지막 적을 기절시키면 탐지가 그를 빼고 실패하므로 **끄러 갈 노드 자체가 안 돌아**, 폰이 아무도 없는 허공을 영원히 휘둘렀다(피해는 표적이 없어 안 들어가 **화면에만 보인다**). **끄는 책임이 한 곳에만 있으면 그 곳이 안 도는 경로에서 반드시 샌다.** 조건을 여기서 다시 적지 말 것 — 갈라 적으면 *트리는 그만뒀는데 팔은 움직이는* 상태가 다른 이유로 또 생긴다. **도는 것은 `PawnMover`가 든다**(`FaceTowards`/`FaceDirection`) — 자세(잠·기절·업힘)를 그쪽이 들고 있어 **밖에서 `rotation`을 만지면 누운 폰을 세우거나 업힌 폰을 어깨 위에서 돌린다**. 수평만 돈다. **싸우는 중이면 표적이 이긴다**(둘 다 쓰게 두면 프레임마다 갈려 몸이 떤다).
- **능동은 폰이 아니라 장비가 준다**(`WeaponData.Ability`/`ArmorData.Ability` → `AbilityUser`) — 갈아입히는 것이 곧 역할을 바꾸는 것이다. JSON 장비는 `abilityId`로 가리킨다. **같은 능력을 두 번 담지 않는다**(칸은 넷인데 쿨다운은 하나면 세 칸이 회색으로 남는다). **횟수는 하루에 한 번 통째로 찬다**(`MaxCharges`, 2026-09-08 사용자 결정) — 쿨다운(*연달아 못 쓴다*)과 다른 물음이지만, **습격은 불규칙해서 일주일도 안 올 수 있으므로** 둘이 실제로 가르는 것은 **한 싸움 안**뿐이다(쿨다운은 얼마나 자주 · 횟수는 모두 몇 번). 그래서 **한 칸씩 차는 시계는 손잡이가 아니었다** — 싸움 사이가 늘 그보다 길어 다음 싸움엔 어차피 가득이다. **`Elapsed`가 아니라 `CurrentDay`로 잰다**(경과 초로 재면 폰마다 차는 순간이 달라 *오늘 몇 번 남았나*를 폰마다 세야 한다) · **비어 있음 = 가득이라 초기화가 지우는 것으로 끝난다**. **아무도 안 걸려도 쿨다운은 돈다**(스탯은 안 는다). **도발은 `DetectNode` 맨 위여야 하고 `TauntedBy`로 따로 든다** — 아래에 두거나 `Target`에 바로 꽂으면 **한 틱 만에 더 가까운 적으로 갈아타** 능력이 아무것도 안 한 것이 된다. 만료·죽음·기절은 **`Taunt.HolderOf` 하나**가 본다.
- **몸의 눈금은 켄시 값이다** — 부위 전부 **100 균일** · 혈액 **100** · 파괴는 **−100 고정**(무력화에서 꼭 그만큼 더). 부위를 가르는 축은 HP가 아니라 **`HitWeight`**(머리 10 · 가슴 18 · 배 16 · 팔 각 13 · 다리 각 15)와 그 부위가 무엇을 하느냐다. **쓰러뜨리는 것은 코어뿐**이라 몸통 비중이 곧 전투 길이다. **그래서 쓰러지는 것은 대개 출혈이고**(베기 15.4대 ↔ 가슴 21.4대) **무기가 그 축을 가른다**(둔기는 부위로, 베기는 피로 눕힌다).
- **`maxBlood`·혈액 계수·`coreKoDepth`·회복률은 `[SerializeField]`라 프리팹이 값을 들고 있다** — **코드 기본값을 고쳐도 이미 있는 프리팹에는 아무 힘이 없다**(`EventManager.checkInterval`이 씬에 박혀 있던 그 함정). 부위 HP와 `BleedRate`는 런타임 생성이라 코드만 고치면 된다.
- **치료의 단일 출처는 `Treatment`**(회복량·속도·약 고르기) — 치료하는 길이 둘(의사·자가)이라 양쪽에 적으면 반드시 어긋난다. **약은 손에 든 것만 쓴다**(창고 것을 원격 소모하면 붕대가 손에 없는데 감긴다) → `TreatJob`은 **2-phase**. **가장 좋은 것을 쓴다**(아끼면 구급낭이 영영 상자에 남는다). **자가치유는 일감이 아니라 `RestNode` 안에 있다**(BT가 `Rest`에서 멈춰 `WorkNode`까지 안 간다 — 일감으로 만들면 아무도 못 집는다). `StatName.Medicine`이 회복량과 속도를 함께 정한다.
- **붙들려 있는 동안은 기절 시계가 안 간다**(2026-09-11, `UnitBlackboard.Restrained` + `CarriedBy`) — 어깨에 메였거나 도축대 상판에 묶인 몸은 쉬는 중이 아니다. 없을 때 **사냥이 통째로 성립하지 않았다**: 업고 가는 데 십수 초 · 상판에서 죽이는 데 7초라 **최소 기절 20초가 그 사이에 지나가** 도마 위에서 깨어나 걸어 나갔다(`ButcherJob`은 *깨어나면 그만둔다*를 지켰을 뿐이다 — **규칙 둘이 각자 옳은데 겹쳐서** 생긴 자리라 어느 쪽을 읽어도 안 보인다). **침대는 안 걸린다**(눕혀 두는 것이 곧 회복이다) — 다만 **둘 다 `SetSleeping`으로 눕히므로 자세로는 구별할 수 없어** 붙드는 쪽이 적어 준다. **놓이면 곧바로 깨어난다**(2026-09-12 사용자 결정 — 멈추기만 하면 쓰러뜨리자마자 업은 몸이 **내려놓고도 18초를 더 서 있다**. 20초는 *맞자마자 벌떡 일어나지 않는다*는 뜻이지 놓인 뒤에 그만큼 더 누워 있으라는 뜻이 아니다 — 업혀 다니는 동안 그 시간은 이미 지났다) — **몸이 이미 나았을 때만**이다(피가 모자란 몸은 제 시계를 그대로 쓴다: *붙들려서 못 일어나는 것*과 *아직 못 일어나는 것*은 다르다). **푸는 자리를 빠뜨리면 영영 안 깨어난다** — 도축대는 `ReleaseLaid`가 풀고, **꺼질 때도 푼다**(`SiteJobSlot.Drop`은 *아직 시작 안 한* 일감만 끊어서 손질 중이던 몸은 아무도 안 풀어 준다). **기절한 폰은 아무도 안 때린다** — `BTTargetUtil.IsAttackable`이 기절·시체를 **모든 자동 경로**에서 뺀다(KO가 사형선고가 아니라 회복 가능한 상태여야 한다). **예외는 `FinishTarget` 하나뿐이고 한쪽 방향뿐이다**(플레이어 우클릭에서만 붙으므로 **쓰러진 우리 폰은 적에게 여전히 안 맞는다**). **언데드는 기절하지 않는다 — 갈리는 자리는 `BodyPartSystem.KnockOut` 하나**(기절로 오는 길이 셋이라 각자 앞에서 물으면 *가끔* 기절하는 해골이 남는다). 딸려 오는 것: **언데드는 산 채로 못 잡는다.**
- **누가 죽든 시체로 남는다 — 내 폰도.** `BecomeCorpse`는 **끄기만 하고 아무것도 안 지운다**(그래서 `UnitBrain.Rise`가 그 짝으로 성립한다). **`Faction` 컴포넌트는 지우되 소속은 `Corpse.Faction`이 기억한다** — 자동 탐지를 끊으려는 것이지 잊자는 뜻이 아니다. 그래서 **"모르는 것은 플레이어가 아니다"**(`faction == null`을 플레이어처럼 대하면 시체가 그 구멍으로 들어온다). **`BodyPartSystem`·`StatusEffectSystem`도 같이 끈다**(안 끄면 시체가 계속 피 흘리고 계속 불탄다).
- **시체가 지녔던 것에 답하는 것은 `Corpse.SpillBelongings` 하나다 — 배낭과 *차고 있던 장비* 둘 다.** 장비는 격자를 안 먹으므로 **배낭만 훑으면 무기·갑옷이 시체와 함께 조용히 사라진다**(도축·화장이 실제로 그랬다). **무덤은 안 부른다**(같이 묻고 파낼 수 있어서 잃는 것이 아니다).
- **시체는 삭되 사라지지 않는다**(신선 1일 → 썩음 3일 → **뼈 영구**) — 그게 매장·화장이 있어야 할 이유이고, **치우지 않은 시체가 습격의 재료가 된다**(`Necromancy`). **일으키는 것은 세력이 답한다**(`FactionData.RaisesDead`/`ExhumesGraves`) — 습격이 오는 길이 둘이라 이벤트 에셋에 적으면 **지도에서 온 교단은 시체를 그냥 지나친다**. `UnitBrain.Rise`가 되돌릴 것 넷: **`Corpse` 제거 · `Faction` 재부착 · 역할과 `Merchant` 제거 · 몸**, 그리고 **`_bb.Faction` 캐시를 같이 갈아 끼운다**(안 하면 일어난 것이 아무도 안 때린다).

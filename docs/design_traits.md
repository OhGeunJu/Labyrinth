# 특성(Trait) 시스템 설계 — 2026-07-26 방향 결정, 구현 추후

림월드식 **이산 특성 태그** 시스템. 폰마다 특성을 여러 개(목표 3개) 랜덤으로 부여하고, **강인함(Toughness)도 스탯이 아니라 특성 중 하나**로 재정의한다.

## 배경 / 문제의식

- 현재 **강인함은 모든 폰이 기본으로 갖는 스탯**(`UnitStats.Toughness = 10f` 기본값). 기절 저항이 `_brain.Stats.Toughness`를 읽음(`BodyPartSystem.TryKnockOut`, `docs/combat.md` 참조).
- 원하는 그림: "**강인함 특성을 가진 폰만** 기절 저항이 있다" — 즉 강인함이 보편 스탯이 아니라 일부만 가진 특질이어야 함.
- 확장: 나중에 **폰마다 특성 3개씩 랜덤** 부여(림월드 방식).

## 결정 사항

1. **모델 A 채택 — 특성은 스탯을 보정(offset)한다.** 기능 자체를 특성으로 게이트(모델 B)하지 않음.
   - 강인함은 스탯으로 유지하되 **기본값을 0/낮게** 깔고, `강인함` 특성을 뽑은 폰만 큰 보너스를 받음 → 실질적으로 "강인한 폰만 기절 저항".
   - 기절 계산 등 `Stats.Toughness`를 읽는 전투 코드는 **그대로**. 특성은 스탯에 숫자만 얹으므로 전투 수식 재작성 불필요.
   - 대부분의 특성을 "스탯 오프셋" 패턴으로 통일 + 일부만 특수 규칙 플래그(예: 흡혈, 야맹).
2. **강인함 스탯 기본값 하향** 은 특성 시스템 전제. 특성 없이 기본값만 낮추면 "아무도 기절 저항 없음"이 되므로, 스탯 하향은 특성 구현과 **동시에** 해야 함(선행 시 밸런스 붕괴).

## 아키텍처 스케치 (구현 시)

- **`TraitData` (ScriptableObject)**: 특성 1종 정의.
  - `TraitName` / `Description` / `Icon`
  - `StatOffsets`: `List<{ StatName, float delta }>` — 스탯 보정(강인함 특성 = Toughness +N).
  - `SpecialFlags`: enum flags — 스탯으로 표현 안 되는 규칙(추후, 예: 통증무시/흡혈).
  - `Weight`: 추첨 가중치. `ExclusiveGroup`: 상호배타 그룹 id(예: 겁쟁이 vs 용감).
- **`TraitPool`**: static 레지스트리(`DataManager` 패턴, `Resources/Data/Traits/` 로드).
- **부여 시점**: 폰 스폰 시 풀에서 가중치 추첨으로 N개(기본 3), 배타 그룹 중복 회피.
  - 진입점 후보: `UnitBrain.Awake`의 `Stats = UnitStats.FromData(...)` 직후 특성 롤 → `Stats`에 오프셋 적용.
  - 미니언(`IsLocked`)·enemy·NPC는 특성 부여 여부 정책 별도(하수인은 고정 스펙일 수도).
- **스탯 적용**: 특성 오프셋을 `UnitStats`에 합산(성장과 분리 — 특성분은 재계산 가능하도록 별도 누적 권장).
- **UI**: 초상화/스탯 패널에 특성 3개 표시(`UnitStatsUI`/`UnitHPUI` 확장).

## 현재 코드 접점 (구현 시 손댈 곳)

- `UnitStats.Toughness` — 기본값 하향 + 특성 오프셋 합산 지점.
- `UnitBrain.Awake` — 특성 롤/적용 진입점.
- `BodyPartSystem.TryKnockOut` — 변경 불필요(그대로 `Stats.Toughness` 읽음). 모델 A의 이점.
- `UnitData` — 종족별 특성 풀/개수 오버라이드 여지(종족 고정 특성 등).

## 열린 질문 (구현 착수 시 결정)

- 특성 개수: 3 고정? 종족/등급별 가변?
- 하수인/적/NPC도 특성을 받나, 아니면 방랑자(플레이어 폰)만?
- 강인함 외에 1차로 넣을 특성 목록(민첩/손재주/겁쟁이/광전사 등).
- 특성 획득/변화가 런타임에 생기나(부상 후 트라우마 등), 스폰 고정인가.

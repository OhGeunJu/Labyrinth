# 월드맵 + 필드맵 + 다중 정착지 설계 — 2026-06-18 결정, 구현 예정

림월드식 **2층 맵 구조**(추상 월드맵 + 디테일 필드맵)로 전환. **거점 중심 모험 게임**을 목표로, 켄시식 단일 심리스 대형 맵 노선(`docs/world.md`·기존 메모)을 폐기한다.

## 비전

타워디펜스(고정 거점 농성) 아님. **거점은 모험의 발판(허브)**, 월드맵은 **탐험 공간**이다.

켄시(열린 탐험·지역별 위험 게이팅) + 림월드(거점 빌드) + 던전 코어(코어 박고 영역/하수인 확장)를 하나로 꿴다.

**핵심 루프:**
```
탐험(월드맵, 안개) → 새 바이옴 발견(용암지대 등) → 그 지역 필드맵 진입해 개척
  → 코어 박음 → 그 바이옴 전용 자원/하수인/연구 해금
  → 그걸로 무장·보급해 더 험한 지역으로 진출 → 반복
```

## 결정 사항

| # | 항목 | 결정 | 근거 |
|---|---|---|---|
| 1 | 장르 | 거점 중심 모험 (타워디펜스 X) | 월드맵 = 위협 컨베이어가 아니라 능동 탐험 레이어 |
| 2 | 맵 구조 | 월드맵(추상 바둑판·안개) + 필드맵(200×200 바운디드) | 던전 1개만 디테일 → 켄시 거대 Terrain 비용 회피 |

| 7 | 뷰 | 파티 추종 X — **내가 선택한 월드/정착지가 보이는 전환형** | 카메라는 활성 필드맵 또는 월드맵 뷰만 |

## 왜 전환형인가 (아키텍처 핵심)

현 코드베이스는 **전역 싱글톤** 천지: `MapManager`, `JobManager`, `Storage.All`(static 집계), `DungeonCore`, `PriorityManager` 등 전부 "맵 하나" 가정.

- **동시 다중 맵(진짜 림월드식)** → 싱글톤을 전부 정착지별 인스턴스로 쪼개야 함. 거대 리팩터.
- **전환형(한 번에 한 필드맵 활성)** → 싱글톤 구조 유지. 맵 전환 시 활성 정착지 상태를 save/load만. 비활성은 오프라인 추상 틱.

→ **전환형 채택.** 디스크 세이브가 없어도 최소한 비활성 필드맵의 **인메모리 스냅샷**(건물 배치·창고·하수인 로스터)은 필요.

## 시스템별 변경 대상

- **`MapManager`** — 바운디드화(0~199 경계). 점유 `HashSet<Vector2Int>` 유지 + 바운드 체크. 활성 정착지 상태를 스냅샷으로 직렬화/복원하는 진입점. 코어 크립 영역 판정은 200×200 안에서 그대로.
- **정착지 스냅샷/직렬화 (신규)** — `SettlementSnapshot`(건물 배치, 점유, 창고 내용, 하수인 로스터, 영역). 활성 전환 시 현재 맵 → 스냅샷 저장, 대상 맵 스냅샷 → 로드. 비활성 동안 오프라인 생산 틱(자원 N/일 누적, 식량 소비, 추상 방어 판정).
- **`WorldMap` (신규)** — `WorldTile{ Biome, Content(마을/소굴/자원/빈칸/내정착지), Discovered }` 2D 배열 + 안개. 바둑판 뷰. 월드 시간 = `GameTimeManager` 일수 축으로 확장.
- **파티/원정 (신규)** — `ExpeditionParty`(멤버 = 방랑자 + 선택 하수인). 편성 시 출발 거점 필드맵에서 멤버 제거, 멤버는 월드맵 추상 토큰으로 이동(일수 경과). 여러 파티 동시. 도착 노드 필드맵 로드 시 멤버 스폰.
- **`EventManager`** — 기존 맵 엣지 스폰 로직을 "월드맵 → 필드맵 디스패치"로 승격. 적/상인이 월드 노드에서 던전 노드로 접근 → 도착 시 필드맵 엣지 스폰.
- **등짐 UI (`PawnInventoryPanel` 확장)** — "파티 뷰 모드" 추가. 같은 멤버 `Inventory` 데이터를 A(멤버별 묶음)/B(합산 공용 풀 + 무게바) 두 방식으로 렌더, 토글 버튼. B 뷰 add = 자동 분배(여유 많은 멤버부터).
- **적재 용량** — 멤버 적재 한도 = `Strength` 파생. 파티 총 적재 = 멤버 합. 무거운 짐 운반 시 근력 성장.
- **바이옴 게이팅 (데이터)** — `WorldTile.Biome` → ResourceNode 풀 + 소환 가능 `MinionData` + `ResearchManager` 해금 조건.

## 구현 단계 (제안)

1. **`MapManager` 바운디드화** — 200×200 경계, 점유 바운드 체크. (켄시 무한맵 전제 제거. 코어 크립은 그대로.)
2. **정착지 스냅샷/전환** — `SettlementSnapshot` 저장/복원, 활성 맵 1개 전환. (오프라인 생산은 step 5로 분리 가능.)
3. **`WorldMap` 데이터 + 바둑판 뷰** — 노드/바이옴/안개, 뷰 토글.
4. **파티 편성 + 월드 이동** — 멤버 선택 UI, 거점에서 제거, 월드맵 추상 이동, 노드 도착 시 필드맵 로드/생성. 코어 박기 → 정착지 승격.
5. **오프라인 추상 생산 틱** — 비활성 정착지 자원 누적/식량 소비/추상 방어.
6. **등짐 뷰 토글 (A/B)** — `PawnInventoryPanel` 파티 모드. Strength 기반 적재.
7. **바이옴 콘텐츠 게이팅** — 전용 자원/하수인/연구 데이터 얹기. (이후 지속 확장.)

## 2026-06-20 갱신 (설계 대화)

- **안개(fog of war) 폐기 → 월드맵 전부 보이게.** 지형/바이옴 다 표시, 노드 내용물도 노출(물음표 X). 발견의 긴장은 콘텐츠 은닉이 아니라 **거리+위험도 게이팅**(켄시식 "보이지만 못 감")으로 이전. → 결정 #2/#7/#7b의 "안개" 전제 제거. `WorldMap.Discovered` 어둠 처리·`WorldNodeContent` 물음표 로직 불필요.
- **월드맵 표현 = 3D 타일 지형 지향.** 로직(WorldTile 그리드)과 렌더(바이옴→높이맵/프롭 3D 지형)를 분리. 현재 `WorldMapView`는 평면 Texture2D 1장 → 추후 3D 지형으로. 필드↔월드 전환을 카메라 줌아웃처럼.
- **씬 전략 = A(같은 씬 카메라 토글) 확정.** 새 Unity 씬 전환(Single load)은 싱글톤 파괴 → 세이브 시스템 전제. 현재는 같은 씬 토글 + 카메라 페이드/줌 연출.
- **거점 수 = "여러 거점, 1개씩 전환" 확정.** 다중 정착지·전환형 = 하이브리드 C(활성 1개 + 나머지 인메모리 스냅샷). 디스크 영속은 후속.
- **★ 코드-설계 갭:** 현 `SettlementManager`는 **B 방식**(정착지 루트 GameObject 사전 배치 + `SetActive` 토글, 비활성도 메모리 상주, 스냅샷 아님). 결정은 C(스냅샷). 지금은 동작하나 거점 증가/런타임 코어박기 생성 시 한계. **다음 작업: B 유지 vs C 이행 결정 → `SettlementSnapshot` 데이터구조 설계**(PlacedBuilding 목록 / 점유 HashSet / Storage 내용 / 하수인 로스터 / 코어 영역).

## 미결 / 주의

- **임시 원정 맵 비관전 처리**: 안 보는 동안(다른 정착지 활성) 원정 파티가 위험 노드에서 전투 중이면 어떻게? 추상 전투 판정 vs "보는 곳만 진행, 나머지 일시정지". 공정성/긴장감 트레이드오프.
- **오프라인 생산 desync**: 추상 틱과 실제 시뮬 결과 괴리 최소화 규칙 필요.
- **여러 파티 동시 이동**: 각 파티가 비활성 정착지처럼 월드맵 시간으로 틱. 동시 다수 시 UI(월드맵에 여러 토큰) 정리.
- **거점 간 물류**: 1차는 파티 등짐만. 전용 운반(팩애니멀/물류 라인)은 후속.
- **세이브 시스템 부재**: 현재 디스크 세이브 없음. 스냅샷은 우선 인메모리. 영속 세이브는 별도 과제.
- **코어 크립과의 관계**: 영역(핵 반경 합집합) 판정은 바운디드 필드맵 안에서 유효(`docs/design_core_creep.md`). 정착지마다 자체 영역.
